## 一页纸

我们要做一个**让 DeepSeek Harness（DSH）具备账号级跨端对话同步能力的开源插件 + 云端控制面**：手机不跑 Agent，只做视图与指令入口；电脑端 DSH 常驻执行，会话日志是唯一真源；云端只存账号、设备注册表和会话索引，不存事件正文、不存工作区文件。

对标体验：WorkBuddy「连接电脑」——同账号自动发现设备、一次配对永久有效、手机和电脑看到同一份会话、任务中发消息进队列、产物回传手机。但我们的实现基于 DSH 插件生态，可自托管、可审计、可 fork。

**核心设计一句话**：不是一个"多端各存一份聊天记录再合并"的同步系统，而是**一个会话、多个视图、一个写入者**。

## 目标 / 非目标

### 目标（v1.0）

- G1 同账号下任意设备可发现并选中一台在线 PC，进入该 PC 上已有会话继续对话。
- G2 手机发消息 → 电脑端同一会话实时出现；电脑端输出 → 手机端实时出现（含流式分片折叠）。
- G3 会话执行中手机继续发消息进队列、共享上下文、不打断当前轮次。
- G4 断线重连按 `seq` 补齐，不丢事件、不重事件。
- G5 产物卡片、置顶任务、工作空间增删、设备名称、定时任务遥控，两端一致。
- G6 文件与工作区始终留在 PC，云端零文件落地。

### 非目标（明确不做，写进 Charter 防止范围蔓延）

- **不做云端执行**：不建云端沙箱，不在云上跑 Agent。
- **不把会话正文上云**：云端只存索引与游标。
- **不做手机本地引擎**：不把 Node/DSH 塞进 APK（那是 dsh-Go 的路线）。
- **不做多人实时协作编辑同一会话**（v2 再评估）。
- **不做 IM 助理渠道接入**（微信/企微/飞书等，v2）。
- **不做跨 PC 会话迁移**：会话绑定创建它的那台 PC；换机执行 = 新会话 + 引用原会话谱系。

## 术语表

| 术语 | 含义 |
|---|---|
| **DSH / dsh** | DeepSeek Harness，开源 Agent 运行框架，Cordis 内核，"一切皆插件" |
| **Host** | 常开的 PC，跑 DSH + 本项目的 host 插件，是唯一执行点 |
| **CP（Control Plane）** | 云端控制面：账号、设备注册表、会话索引、路由租约 |
| **Relay** | 自托管中继：配对、挑战响应、WS 帧透传、HTTP 反向代理 |
| **SessionEvent** | DSH append-only 事件日志中的单条记录，含 `type / seq / time / data / ignorable?` |
| **seq** | 会话内单调递增、连续无间隙的事件序号，等于 `log.length`，用作断线补齐游标 |
| **Surface** | 会被投影成模型消息的四类事件：`system/message`、`user/message`、`assistant/message`、`tool/result` |
| **Bundle** | 可安装的 npm 包，带 `dsh.bundle` manifest 与 `cordis.patch.yml` |
| **Client 半边** | `dsh.client` manifest 声明的浏览器侧扩展，提供设置页 / 侧栏入口 |
| **Profile** | DSH 的可运行组合单元（如 `web`），`dsh --profile web` 启动 |
| **单写者租约** | 同一会话同时只允许一个写句柄，第二个 `open(id,'write')` 抛 `SessionAlreadyOwnedError` |
| **Route / Lease** | 控制面记录的"某会话当前由哪台 Host 持有写句柄" |
| **Cursor** | 每个客户端的消费位点 `sinceSeq` |
| **surfaceOp** | 宿主事件自带的投影指令（实测恒为 `append`），客户端据此更新视图 |
| **sourceEventSeqs** | 事件关联的源事件 seq 数组；实测仅出现在 `tool/result`，用于配对 `tool/call` |
| **requestId** | 宿主 `prompt(request)` 的幂等键，由 `clientMsgId` 直接映射（见 ADR-008） |
| **多帧 zstd** | `session.v4.jsonl.zstd` 的存储格式：每批追加写一个独立 zstd 帧，须逐帧解压；只解首帧会漏读全部事件 |

## 开工前必须确认的三件事

1. **锁定 DSH commit**：已锁定 `66491b05e3f05ad35bcdd4f6cd7ed26041d9e3db`（上游 tag `dsh-v0.2.2-rc.1`，见 `pinned-commit.txt`）。上游已开始使用 release tag，但 DSH 仍处 Developer Preview，升级一律走独立 ADR。
2. **环境基线**：Node.js ≥ 24.9（带 TS type stripping）、pnpm 11.x（Corepack 管理）、`NODE_OPTIONS` 不含 `--no-experimental-strip-types`。
3. **信任边界**：Host 主动外连 Relay，PC 不开入站端口；Relay 只做帧透传，不解析会话内容。
