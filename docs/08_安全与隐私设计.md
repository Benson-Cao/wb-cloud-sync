# 08 安全与隐私设计

> Owner：架构师（兼安全 Owner）｜ 版本 v1.0 ｜ 安全项拥有一票否决权

---

## 1. 安全目标（CIA 排序）

1. **机密性**：会话正文零落盘、零进入 CP（但**经 Relay 明文转发，运维可见**，见 `04` §5.4 / ADR-010）；工作区文件、本地配置绝不离开 PC；令牌不明文落盘。
2. **完整性**：事件序不可篡改、写入权唯一、消息不重不丢。
3. **可用性**：Relay SLO 99.5%，但明确依赖 PC 在线；PC 离线是产品预期而非故障。
4. **可审计**：设备、配对、吊销、端点调用全留痕；日志不含敏感正文。

## 2. 信任边界

```
┌─ 不可信：公网 / 手机设备丢失场景 ─┐
│ 手机 PWA                          │
└──────────────┬───────────────────┘
   边界① 账号鉴权 + 设备令牌 + TLS
┌──────────────▼───────────────────┐
│ CP（账号/索引）  ←→  Relay        │  边界② 服务间信任 + HOST_TOKEN
└──────────────┬───────────────────┘
   边界③ 设备令牌 + HMAC 挑战响应 + 白名单
┌──────────────▼───────────────────┐
│ Host PC（可信执行点）             │
│ DSH + 插件 + ~/.dsh 事件日志      │
└──────────────────────────────────┘
```

- **Relay 是半可信**：可转发帧、不解析语义、不写盘；但 **TLS 在 Relay 终止，Relay 进程可见事件帧明文（含会话正文）**，这是 v1 的已知边界（`04` §5.4 / ADR-010）。工作区文件根本不经过它，即使 Relay 被攻破也拿不到文件；**会话正文的机密性依赖「自托管 + 运维可信」，不依赖密码学隔离**。
- **CP 是半可信**：只持有元数据；即使泄露，也不含对话正文。
- **Host 是唯一可信执行点**：文件、模型密钥、工具权限都在这里。

## 3. 威胁模型（STRIDE 摘要）

| 威胁 | 场景 | 缓解 |
|---|---|---|
| **S** 假冒 | 攻击者伪造 Host 注册 / 伪造手机 | `HOST_TOKEN` 服务间鉴权；配对码 + HMAC 挑战响应；`deviceId` 稳定绑定账号 |
| **S** 假冒 | 配对码被猜中 | 6 位码 10min TTL + 设备/IP 限速 5 次/分 + 一次性挑战 60s |
| **T** 篡改 | 中继改帧、重排 seq | 帧按 ≤64KiB 保序搬运；客户端按连续 seq 校验，缺口不渲染；TLS 全链路 |
| **T** 篡改 | 双端同时写撕裂日志 | Route Lease 单写者，冲突 409；插件侧静态检查禁止 `open(id,'write')` |
| **R** 抵赖 | 谁发的消息说不清 | `clientMsgId` + 设备指纹 + 结构化审计日志 |
| **I** 信息泄露 | 会话正文/文件上云 | 架构性保证：CP 无正文表、无文件接口、Relay 不写盘；出网审计验证「**自动路径** 0 字节工作区文件 + 0 条正文写入持久化层」（显式导出见 ADR-011）；**Relay 运维可见明文正文由 ADR-010 显式登记，靠自托管与主机加固缓解** |
| **I** 信息泄露 | 令牌明文落盘 | 只存 `SHA-256(deviceToken)` 摘要；管理台只显示令牌指纹 |
| **I** 信息泄露 | 日志打印正文 | 日志字段白名单，禁止 `data` / token / 文件内容；CI 做正则扫描 |
| **D** 拒绝服务 | 重试风暴打满 Relay | `clientMsgId` 去重窗口、限速、10s 无进度防悬挂、host 离线立即 409 |
| **E** 提权 | 手机调用文件/命令类端点 | `allowedEndpoints` 白名单默认仅 `session/*`、`$events/*`；高危权限默认全关闭 |

## 4. 身份、配对与令牌生命周期

### 4.1 配对

```
PC 显式开启「允许移动端连接此设备」→ 生成配对码
  · 6 位、10 分钟 TTL
  · 设备 + IP 维度限速 5 次/分钟
手机输码 → 一次性挑战（60s）→ HMAC-SHA256 响应 → 签发 deviceToken
```

- 二维码**仅作下载引导，不参与配对**（与 WorkBuddy 一致）。
- 设备关系持久保留，一次配对永久有效；**重新配对自动替换该设备旧令牌**。

### 4.2 令牌

| 规则 | 说明 |
|---|---|
| 存储 | 只落 `tokenDigest = SHA-256(token)`，绝不存明文 |
| 活跃数 | 单设备仅 1 个活跃令牌 |
| 重连 | 持令牌静默重连，不重复走配对 |
| 吊销 | 管理台一键断开手机 / 吊销设备 / 删除设备；删除写**真墓碑**，重启不复活 |
| 清理 | 孤儿令牌、30 天前已吊销令牌，服务加载时自动清理 |
| 状态 | `$DSH_HOME/mobile-remote/devices.json` 保存设备与配对状态 |

### 4.3 账号

- OAuth（Google / GitHub）主体为账号唯一标识；同一 provider 的同一 `sub` 视为同一用户。
- 账号级同步范围：设置、Assistant 配置、自动化定义、Memory、偏好。
- **账号不授予会话访问权**：能看哪些会话由 `Device.accountId` + 设备绑定关系决定，不是"登同账号就能看所有会话"。

## 5. 权限模型

```yaml
allowedEndpoints:
  - 'session/*'
  - '$events/*'
```

- 默认拒绝一切其余端点；新增端点必须走 ADR + 白名单评审。
- 高危能力（命令执行、文件写入、读屏、点按输入）**默认全关闭**，逐项显式授权；涉及账号/密码输入类场景单独二次确认。
- 手机端对 `pinned / pinnedOrder` 只读，置顶与调序只能 PC 端发起。
- 产物下载用**短期临时票**：过期 / 重放拒绝，不暴露 PC 本地绝对路径。

## 6. 数据与隐私

| 数据 | 存放位置 | 是否上云 |
|---|---|---|
| 会话事件正文 | PC `~/.dsh`（唯一持久副本） | **否**（零落盘、不进 CP；仅在 Host↔手机事件流中经自托管 Relay 实时转发，运维可见明文，见 `04` §5.4） |
| 工作区文件 / 生成产物本体 | PC 本地 | **否** |
| 本地配置、模型密钥 | PC 本地 | **否** |
| 会话索引（标题/状态/lastSeq/workspace 名） | CP | 是（元数据） |
| 设备名、平台、能力、在线状态 | CP | 是 |
| 账号设置 / Memory / 自动化定义 | CP | 是 |
| 令牌 | 仅摘要 | 摘要 |
| 产物元数据 + 下载票 | CP / Relay 临时 | 是（元数据） |

**产品层必须说清**：手机查看历史消息必须连上对应在线 PC；PC 离线时只能看索引与状态点。这不是缺陷，是"文件不出本机"的代价。**另须说清**：会话正文本来就要经过 Relay 才能到手机，v1 保证的是「不落盘、不进 CP、文件零出网」，不保证「Relay 运维看不到正文」；因此 Relay 必须自托管，见 `04` §5.4。

**出网审计**：W10 用流量镜像 + 存储层扫描证明 **自动路径 0 字节工作区文件出网**、**0 条会话正文写入 CP / Relay 持久化层**；报告进 GA 门禁。「正文经 Relay 实时转发」是协议既定行为（`04` §5.3），**不得**写成「0 条会话正文经过 Relay」，否则用例必然失败（ADR-010）。

## 7. 传输与网络安全

- 全链路 TLS 1.2+；WSS 与 HTTPS 均校验证书，禁止自签跳过。
- **PC 零入站端口**：Host 主动 WSS 外连 Relay，符合企业网络策略。
- `bind` 配置默认不建议 `0.0.0.0` 裸暴露本地插件端口；调试仅限回环 `127.0.0.1`。
- 本机引擎场景（若未来支持）只监听回环，外部访问不到。
- Relay 只做帧透传，不缓存会话内容；请求/响应按 ≤64KiB 帧搬运，帧序即流序。
- 10s 无进度防悬挂，Host 离线立即 409，避免连接被恶意挂住。

## 8. 审计与可观测

**必须记录的事件**：设备注册 / 下线、配对码生成与核销、令牌签发与吊销、端点拒绝（`ENDPOINT_NOT_ALLOWED`）、路由冲突 409、审批作答、产物下载票签发。

**日志字段白名单**：
```
ts, level, component, accountId, deviceId, sessionId, seq, event, code, traceId
```
**禁止**：`data`（事件正文）、`deviceToken`、文件内容、本地绝对路径、Authorization 头。CI 加正则扫描拦截。

**监控指标**：在线设备数、帧延迟直方图、错误码计数、补齐失败率、令牌吊销次数、出网字节数（文件通道应为 0）。

## 9. 供应链与运行时

- 锁 DSH commit（`pinned-commit.txt`），CI 校验一致；依赖锁文件入库。**取证脚本从宿主 `app.asar` 抽取的源码片段不得随公开仓库发布**，证据输出默认脱敏（见仓库 `spike/probe-host.mjs`）。
- 发布走 npm provenance（`--provenance`）；Release 流水线校验 tag 与 `package.json` 版本一致。
- 从 GitHub 直装可能触发 pnpm `allowBuilds` 拦截；**交付 `pnpm pack` tarball 或 npm 包**，不让用户手动放宽构建脚本授权。
- 插件所有注册经 `ctx.effect` 可逆；卸载后无残留路由 / 定时器 / WS 连接（`07` TC-4.10）。
- 配置用 `Schema` 校验并补齐默认值，拒绝未声明字段；不把部署相关取值硬编码。

## 10. 合规检查单（GA 前）

- [ ] 令牌无明文落盘，管理台只显示指纹
- [ ] 配对限速 / TTL / 挑战超时三项生效
- [ ] 白名单外的端点全部 403
- [ ] 高危权限默认全关闭，逐项授权可审计
- [ ] 吊销 / 删除 / 墓碑 / 重启不复活验证通过
- [ ] 出网审计：**自动路径** 0 字节工作区文件、0 条会话正文写入持久化层
- [ ] 日志正则扫描无敏感信息
- [ ] 产物下载票过期与重放拒绝
- [ ] 依赖锁与 pinned commit 一致，发布带 provenance
- [ ] 渗透用例（TC-7.1~7.8）全绿，无高危项

## 11. 事件响应

| 场景 | 动作 |
|---|---|
| 手机丢失 | 管理台吊销该设备令牌 → 在线连接断开 → 重新配对 |
| 令牌泄露 | 一键吊销全部手机会话；旧令牌立即失效 |
| Relay 被入侵 | 因不解析/不缓存正文，轮换 `HOST_TOKEN` + 全量令牌吊销即可，无需轮换会话 |
| 疑似日志撕裂 | 停止该会话写入，走 DSH resume 恢复；**禁止手工截断日志** |
