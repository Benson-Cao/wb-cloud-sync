# 07 测试计划与验收标准 v2

> Owner：QA ｜ 版本 v2.0 ｜ 门禁来源：`02` §6

---

## 1. 测试策略

v2 的核心风险从「单链路一致性」变成**「多真源隔离 + 手机端运行时存活」**，投入重排：

| 层 | 占比 | 重点 |
|---|---|---|
| **真机 / Termux 运行时** | 30% | 冷启动、保活、安全模式、发热、厂商 ROM、launch token |
| 契约 / 一致性 | 25% | hostId 隔离、seq、幂等、commit 漂移、工具卡限额 |
| E2E 三档案链路 | 20% | on-device / ssh / relay 各跑一遍 |
| 混沌 / 恢复 | 15% | 断连、乱序、引擎崩溃 |
| 性能 / 兼容 | 8% | 冷启动、P95、PC 三平台、iOS PWA |
| UI 交互 | 2% | 主机切换确认、状态点、产物卡 |

## 2. 测试环境

| 环境 | 组成 | 用途 |
|---|---|---|
| `local` | docker-compose（CP+Relay+Postgres）+ 本机 DSH `wbsync-dev` profile | 开发自测 |

## 4. 混沌测试方案

`chaos-proxy` + 引擎 kill，随机组合、单轮 200 次：

| 故障 | 注入 | 观察点 |
|---|---|---|
| 随机断连 | 每 2–15s 断 WS | 补齐完整率、重连耗时 |
| 乱序 / 重复帧 | shuffle + 重放 | seq 归位、幂等丢弃 |
| 延迟抖动 | 20–1500ms | P95、超时退避 |
| **Termux 引擎 SIGKILL** | 杀 node 进程后重启 | 安全模式 / 恢复、resume `interrupted`、会话不丢 |
| Relay 滚动重启 | — | 静默重连、令牌保留 |
| CP 不可用 | 停 Postgres | 降级为本地可读索引，写入明确失败 |
| **hostId 错投** | 故意带错 | `HOST_MISMATCH`，不串会话 |

**通过标准**：0 丢 / 0 重事件、0 双写、0 串会话、0 文件外泄、0 launch token 泄漏，所有失败有明确错误码。
