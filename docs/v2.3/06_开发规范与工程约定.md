## 1. 环境基线（双端）

| 项 | PC 侧 | **Termux 侧（新增）** |
|---|---|---|
| OS | Win / macOS / Linux | Android 8.0+ / arm64 |
| Node | **≥ 24.9**（带 TS type stripping） | 满足 pinned commit 的 engines，安装后校验 |
| 包管理 | pnpm 11.x（Corepack） | `pkg install nodejs git`；`npx @deepseek-ai/dsh` |
| DSH | **pinned commit** | **同一 pinned commit** |
| 启动 | `dsh --profile web` | `dsh web --host 127.0.0.1 --port 3080 --no-open` |

> `NODE_OPTIONS` 中**不得**含 `--no-experimental-strip-types`；社区脚手架 engines 口径与官方略有差异，统一按 24.9+ 对齐。
> Termux 必须从 **F-Droid / GitHub Releases 官方渠道**安装，不用应用商店旧版本。

### 常用命令

```bash
# PC：查看组合插件树
dsh --profile web --dump-config
dsh --profile web --dump-default-config
dsh --dump-config-schema

# PC：独立开发 profile
dsh plugin --profile wbsync-dev add ./dsh-wb-cloud-sync

# Termux：安装本地插件（绝对路径，链接目录勿删）
dsh plugin --profile web add /absolute/path/to/my-plugin
```

## 2bis ★ 官方原生 UI 与 Carrier 工程规范（v2.3 / D-005）

**官方原生 UI**：`dsh web` v0.2.2-rc.1 已内置窄屏适配。三档案 WebView 直接寻址官方服务——本机 `127.0.0.1:3080`、SSH 隧道 `127.0.0.1:3081`、Relay HTTP·WS 反代。**不写 UI、不写皮肤、不托管 UI 资源、不做 UI 哈希校验**。

**四条硬约束**：
- **不装第三方窄屏适配插件**（`dsh-client-ui-mobile` / `dsh-pocket-ui` / `dsh-mobile` 等）：官方已内置，叠加会互相覆盖；
- `pinned-commit.txt` 锁 v0.2.2-rc.1 对应 commit，PC 与 Termux 双端一致；该版本为 rc，升级单开 ADR + 官方窄屏冒烟；
- App 仅写 **Kotlin 原生页面**：主机切换器 / 配对页 / PC 离线页（非 Web UI 皮肤）；
- **不做视图快照 / Golden Fixture / `renderContract`**：一致性由「同一个官方 Web UI」天然保证。

**Carrier 骨架**（`packages/client-core/`，纯 TS、无 UI 依赖、不给 UI 供数）：

```ts
interface DshCarrier {
  readonly supportsUplink: boolean
  allowsEndpoint(endpoint: string): boolean
  call(endpoint: string, args: unknown): Promise<RpcOk | RpcError>
  openLink(opts: LinkOpts): DshMuxLink  // item|end|error 帧 / cancel / onLost
}
// LocalCarrier | SshCarrier | RelayCarrier
// 重连、generation、watch() 重同步全部在 DshMux，与传输无关
```

- **禁止**在 App 里 `switch(hostKind)` 写业务分支；差异只允许出现在 carrier 实现里。
- 能力由 carrier 自报（`supportsUplink` / `allowsEndpoint`），被拒统一映射 `ENDPOINT_NOT_ALLOWED`，进 `unauthorized` 等显式重连；**禁止硬编码档案能力差异**。
- **已删除**：`uiBundleVersion` / `X-UI-Bundle-*` / `UI_BUNDLE_MISMATCH` / `RENDERER_VERSION_MISMATCH` / `renderContract` / Golden Fixture。
- 上游升级时只改插件与 `pinned-commit`；**APK 里没有 UI 需要跟**。

## 3. Cordis 插件规范（**仅 PC 侧**）

### 3.1 形态

- 优先函数形态：具名 `name` + `apply(ctx, config)`；需长期持服务才用 `Service` 类。
- **函数形态具名导出与对象/类默认导出不可混写**，混写会被静默忽略一半。
- `name` 唯一可读，禁 `plugin` / `main`。

### 3.2 最小骨架

```ts
import type { Context } from '@deepseek-ai/cordis'
import Schema from '@deepseek-ai/schemastery'

export const name = 'wb-cloud-sync'
export const inject = ['webServer', 'sessionPersistence']

export interface Config {
  relayUrl: string
  hostToken: string
  autoConnect: boolean
  allowedEndpoints: string[]
}
export const Config: Schema = Schema.object({
  relayUrl: Schema.string().required(),
  hostToken: Schema.string().required(),
  autoConnect: Schema.boolean().default(true),
  allowedEndpoints: Schema.array(Schema.string())
    .default(['session/*', '$events/*']),
})

export function apply(ctx: Context, config: Config) {
  ctx.effect(() => {
    const ws = connectRelay(config.relayUrl, config.hostToken)
    const off = ctx.on('session/event', (sessionId, ev) => {
      ws.send({ t: 'session/event', hostId: HOST_ID, sessionId, ev }) // 原样透传 seq
    })
    return () => { off(); ws.close() }
  })
}
```

### 3.3 五条铁律

1. 依赖用 `inject` 声明，不轮询等待。
2. 所有注册都是 effect：`ctx.on()` / `ctx.effect(() => disposer)` 自动清理；定时器、WS、前台服务绑定必须返回 disposer，否则热重载泄漏。
3. `register()` 返回的 disposer 必须交 `ctx.effect()`。
4. 配置用 **schemastery**，不用 zod；默认值写 schema，`apply` 拿到全量配置。
5. **绝不 `open(sessionId, 'write')`**：每台主机内单写者，第二个写句柄抛 `SessionAlreadyOwnedError`；投递交该主机会话 owner。

### ~~3.4 ★ slots 与 Conversation node（手机宿主插件）~~〔**v2.1 / D-003 已废止**，改见 `11` §2 的 `client-core` + `Renderer` 规范〕

```ts
export const inject = ['slots'] as const

declare module '@deepseek-ai/dsh-client-ui-slots' {
  interface SlotMap {
    'shell.overlay': { kind: 'list'; scope: 'root' }
  }
}

export function apply(ctx: ClientContext) {
  ctx.inject(['slots'], (scope) => {
    const dispose = scope.slots.inject('shell.overlay', () =>
      scope.slots.register(
        { name: 'shell.overlay', id: 'wbStatus' }, StatusChip))
    return () => dispose()
  })
}
```

- 往**已声明**的槽位注册；注册进未声明槽位会在插件激活时失败。
- `scope` 四档：`root` / `session-maybe` / `session` / keyed；`priority` 小者先。
- Conversation node 用稳定 `(kind, id)` 匹配事件族：每条事件必须自带 id 或能独立推导；**客户端绝不把 update 猜成"最近未完成的 Context"**，每个 `(kind,id)` 最多一条 start。
- 注册与声明遵循 Cordis effect 生命周期；dispose 条目会递归折叠它声明的子槽。

### 3.5 ★ 工具卡（跨主机唯一 UI 扩展）

- 插件只交清单 + JSON 视图，客户端用自己的组件渲染，**不执行插件代码**。
- 限额：面板视图 ≤32KiB、单卡 ≤8KiB、数据合并 ≤4Hz、效果窗口 3s。
- 未知组件显示灰色占位；清单校验失败只丢弃该条目并标注问题数；连续 5 次违规整体降级为 web 版本。
- 工具卡随 `SessionEvent` 落日志 → 任何主机可读 → 这是远程档案下唯一可用的插件 UI。

## 4. 打包与安装

```jsonc
{
  "name": "dsh-wb-cloud-sync",
  "version": "0.2.0",
  "type": "module",
  "main": "dist/index.js",
  "files": ["dist", "client", "cordis.patch.yml"],
  "engines": { "dsh": ">=<pinned>" },
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": { "entry": "./client/index.js" }
  }
}
```

- `dsh.bundle` 才会被 `dsh plugin add` 加入 profile bundle stack；只有 `dsh.client` 的包只作普通依赖、不自动激活。
- client 半边元数据有进程内缓存 → **首次安装后重启一次引擎 / DSH**。
- `lib/` 代码变更需重启引擎；`package.json` 清单变更按 mtime 重读；移除重加不会重载已加载代码。
- 交付 **npm 包或 `pnpm pack` tarball**，不让用户在 Termux 里处理 pnpm `allowBuilds` 授权。
- 一个包可同时带 `dsh.client` 与手机原生清单：Web UI 忽略手机清单，App 用清单渲染原生插槽，互不干扰。

## 5. ★ Termux / Android 工程约定

### 5.1 启动链路

```
前台服务 → Termux 执行 dsh web --host 127.0.0.1 --port 3080 --no-open
 → stdout 解析一次性 launch token
 → WebView 打开 http://127.0.0.1:3080/?token=… 换 cookie
 → 后续 HTTP/WS 全带 cookie；覆盖 Host 头、不带 Origin
```

- **只绑回环**：禁止 `--host 0.0.0.0`；CI 做静态检查。
- launch token **绝不落日志、不写文件、不进崩溃上报**；只在内存里传给 WebView。
- 引擎状态机 `starting → running | safe-mode | failed`；连续两次失败自动安全模式（不加载插件，会话保留）。
- 引擎重置会清空本机会话 / 工作区 / 插件 / 设置 → 必须二次确认 + 先导出提示；无一键完整备份，文档需说明。

### 5.2 保活

- 前台服务 + 常驻通知；引导关电池优化、最近任务锁定。
- 检测到被系统杀掉 → 10s 内提示并直达 vivo / 小米 / 华为 / 荣耀 / OPPO 放行设置；**"直达设置"不等于"一定放行"**，文案不得承诺。
- 发热 / 耗电 / 约 1GB 存储使用前明示；长任务提示接电源或改远程主机。
- 首次安装约 1GB 数据落盘、冷启动需几秒（Node 加载插件），产品层给进度。

### 5.3 分发

- APK 侧载，**签名必须固定**：签名不同无法覆盖安装，卸载会清空 Termux 环境、对话与设置。
- 不上 Google Play；Termux 由用户自行从官方渠道安装。
- 升级时普通引擎更新只替换 App 管理的组件，保留工作区与配置；Node 大版本变化需重新编译原生扩展。

## 6. 编码约定

- TypeScript strict；禁 `any` 逃逸 `ctx`；事件/帧/接口字段全部只读，`SessionEvent` 深冻结后透传。
- 命名统一：`hostId / sessionId / seq / sinceSeq / clientMsgId / dshCommit`，禁别名。
- **所有索引、幂等、游标、路由键必须带 `hostId`**；跨主机请求校验不一致即 `HOST_MISMATCH`。
- 错误一律走 `04` 错误码表；日志结构化 `{ts,level,component,hostId,sessionId,seq,event,code,traceId}`，**禁打印事件 `data`、token、launch token、文件内容、本地绝对路径**。
- 时间 Unix 毫秒；所有网络调用设超时，Relay 侧 10s 无进度即断。

## 8. CI / CD

**CI**：ubuntu / macOS / windows 三平台 + Android 构建 → install → typecheck → build → test → `pnpm pack --dry-run` → `check-plugin.mjs` → **双端 `pinned-commit.txt` 一致性校验** → 回环绑定静态扫描 → 日志敏感正则扫描。

**Release（tag `v*`）**：tag 与 `package.json` 版本一致 → 全量测试 → `npm publish --access public --provenance` → Relay 镜像 → **固定签名 APK** → CHANGELOG。

**发版顺序**：PROTOCOL → Relay/CP → 两端插件 → Android APK / PWA。协议先发。

**回滚**：组件独立版本；APK 签名固定避免卸载清环境；插件 `dsh plugin remove` + 配置备份还原；出问题时切换到另一主机档案继续工作。

## 9. 版本锁定与升级

1. `pinned-commit.txt` 唯一真源，CI 校验 **PC 与 Termux 双端**一致。
2. 上游升级单开 ADR：全量契约 + E2E + 双端回归 + 破坏性变更清单。
3. 升级只在里程碑之后；禁止运行中 profile 直接 `pnpm update`。
4. Termux 侧 Node 版本变化需重跑安装引导并校验 `engines.dsh`。
