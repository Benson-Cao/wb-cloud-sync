# 11 · D-003 集成方案与变更单

> 决策编号：**D-003**「电脑端做插件，手机侧不做插件，能力集成到 App 内」
> 基线：v2.0（D-002 Termux 双主机版）
> 生效版本：**v2.1**
> Owner：架构师 ｜ 会签：PM / 安全 Owner / QA
> 日期：2026-11-13
> **⚠ v2.3 覆盖声明（历史文档）**：本文件关于「App 自研渲染器（甲方案）」的条款已被 `11_D-004`（D-004）作废；D-004 的「ui-bundle 双投放」又已被 **`13_官方原生UI收口修订单.md`（D-005）作废**。
> **现行方案：手机界面 = 官方 `dsh web` 窄屏原生呈现**；三档案 WebView 直接寻址官方服务；仓库里无 UI 源码、无皮肤、无 UI 契约字段。
> 优先级：`13` > `11_D-004` > `12_实施步骤手册` > 本文件 > 00–10。
> 本文件继续有效的部分：PC 唯一插件、手机不做插件、Termux 原版 DSH、协议内置卡片、`hostId` 命名空间。

## 0. 决策摘要

| 项 | v2.0 | **v2.1（本决策）** |
|---|---|---|
| PC 侧 | `dsh-wb-cloud-sync` bundle | **不变，唯一插件点** |
| 手机侧 | 手机宿主插件 + slots + 工具卡声明 | **不做插件，全部 App 内置** |
| 手机 UI | WebView 加载 DSH 官方 Web UI | **App 自研渲染器**（client-core + 原生组件） |
| Termux | 跑我们的插件 | **只跑原版 DSH**，不装我们的包 |
| 工具卡 | 插件声明的 JSON 视图 | **协议内置卡片类型**，App 原生渲染 |
| 视图一致性 | 靠「同一套官方 Web UI」 | **靠契约 + 对拍测试**（见 §6） |
| 团队 | 10 人 | **9 人**（HE-MB 转 App 客户端，或并入 FE） |
| 一致性风险 | 低（同源渲染器） | **升高 → R-29，必须用 TC-5.14 兜住** |

**一句话**：把插件收敛到 PC 一侧，手机彻底变成「按协议画画」的原生客户端。换来的是包更薄、iOS/Android 可共用渲染器、手机侧攻击面归零；代价是**不能再靠"同一套渲染器"白拿一致性**，必须自己把它做成可验收的契约。

## 2. 手机 App 内置模块清单

| 模块 | 职责 | 是否依赖 DSH |
|---|---|---|
| `client-core` | 协议客户端：REST / WS / 帧重组 / 幂等 / Cursor / 错误码 | ❌ 纯协议 |
| `Renderer` | **把 SessionEvent 序列折叠成视图模型**（本决策核心） | ❌ 按协议实现 |
| `HostSwitcher` | 三档案、切换确认、当前执行位置常驻 | ❌ |
| `SessionList` | 按 `(hostId, sessionId)` 分组、四态状态点、置顶只读 | ❌ |
| `ChatView` | 消息气泡、工具调用折叠条、队列胶囊、停止按钮 | ❌ |
| `CardRegistry` | 协议内置卡片的原生组件注册表（产物 / 审批 / 指标 / 表格） | ❌ |
| `Attachment / Artifact` | 上传、临时票下载、三种格式导出 | ❌ |
| `EngineBridge`（Android） | Termux 启停、launch token 换 cookie、前台服务、保活、安全模式 | ⭕ 只调 `dsh web` HTTP API |
| `iOS PWA` | **复用 client-core + Renderer** 的 Web 构建，仅 ssh / relay 档案 | ❌ |

> 关键收益：`client-core` 与 `Renderer` 是同一份代码，Android 原生与 iOS PWA 共用 → **两端视图天生一致**，比 v2.0 的"Android WebView 加载官方 UI / iOS 自研 PWA"更整齐。

## 4. 接口契约（App ↔ 外部）

```
# CP（账号与索引）
GET  /api/me                       账号 / 设置
GET  /api/me/hosts                 HostProfile[]（kind/state/dshCommit/caps）
GET  /api/sessions?hostId=&pinned= SessionIndex[]
POST /api/hosts/select             { hostId, confirmNoMigration:true } → endpoint
POST /api/sessions                 指定在线主机新建工作空间
POST /api/hosts/:id/revoke

# Relay（远程档案）
POST /pair · /pair/verify          配对与挑战响应
WS   /d/<hostId>/events/*         事件流（帧透传）
ANY  /d/<hostId>/session/*        prompt / cancel / follow
ANY  /d/<hostId>/$events/*        审批作答

# 本机 / SSH 档案（直连 dsh web）
http://127.0.0.1:3080 或 :3081   原版 DSH Web API + launch token → cookie
```

**App 不再调用任何 `/dsh-go/*`、slots、contributions、views 接口。**

响应统一带 `X-Protocol-Version: wbsync/2.1` / `X-Host-Id` / `X-Dsh-Commit`；错误码沿用 `04`，新增：

| code | 含义 |
|---|---|
| `RENDERER_VERSION_MISMATCH` | App 渲染器版本与协议声明的渲染契约不兼容，提示升级 App |

## 5. 工具卡 → 协议内置卡片（简化）

v2.0 里工具卡由插件声明、经桥接转成 JSON 视图，还要管清单校验、限额、降级。v2.1 手机不做插件，这层直接塌缩：

```jsonc
// 仍是随 SessionEvent 落日志的事件，但类型由协议定义
{
  "t": "wbsync/card",
  "cardId": "artifact:report-001",
  "kind": "artifact | approval | metric | table",
  "schema": 1,
  "view": { /* 协议规定字段 */ },
  "actions": [ { "id": "allow", "label": "允许" } ]
}
```

| 项 | v2.0 | **v2.1** |
|---|---|---|
| 谁产生 | 插件声明 | **PC 插件 / DSH 侧按协议发** |
| 谁渲染 | 任意客户端 + 桥接 | **App `CardRegistry` 原生组件** |
| 限额校验 | 插件清单校验器 | **协议 Schema 校验（服务端 + App 双检）** |
| 未知 kind | 灰色占位 / 连续 5 次降级 web | **灰色占位，不降级** |
| 插件代码在客户端 | 不执行 | **根本不存在** |

`kind` 是**封闭枚举**，新增必须升 `schema` + 走协议变更。这比"插件随便声明视图"更可控。

## 6. ★ 视图一致性怎么保证（本决策最大代价）

v2.0 能说"手机加载的就是 PC 官方 Web UI，同源所以一致"。v2.1 App 自研渲染器，**这个白拿的保证没有了**。必须用三层把它补回来：

### 6.1 把渲染规则写成协议的一部分（契约级）

在 `04` 新增 **§4.1 渲染一致性契约**，把以下规则从"客户端各自实现"提升为"协议规定"：

| 规则 | 规定 |
|---|---|
| Surface 投影 | 仅 `system/message`、`user/message`、`assistant/message`、`tool/result` 产生消息 |
| 结构事件 | `turn/*`、`step/*`、`request/*`、`todo/*`、`hook/*`、`session/end-seed` 不进消息流 |
| 流式折叠 | `assistant/chunk` 按 `sourceEventSeqs` 折叠为对应 `assistant/message`；未完成时不单独刷屏 |
| 工具配对 | `tool/call` 与 `tool/result` 按 `callId` 配对 |
| 压缩 | `compaction/start→summary→end` 遮蔽旧节点，**视图缩短、日志原文不变、禁止回写** |
| 顺序 | 严格按会话内连续 `seq`；缺口未补齐时等待，不猜测、不补写 |
| 未知事件 | `ignorable: true` 跳过；不带标记的未知类型进诊断日志但不中断渲染 |
| 状态点 | 四态由 `turn/start` / `$events` 待答 / `turn/end` / 读取失败推导 |

协议带 `renderContract: 1` 版本字段；App 启动时上报 `rendererVersion`，服务端不兼容回 `RENDERER_VERSION_MISMATCH`。

### 6.2 Golden Fixture（防止两端实现漂移）

维护一组固定事件序列样本（含 chunk、compaction、工具调用、崩溃恢复 `interrupted`、工具卡），产出**期望视图模型快照**。PC 插件侧、App 侧、iOS PWA 侧跑同一份 fixture，输出必须逐字节一致。这是 CI 门禁，不是人工检查。

### 6.3 双端对拍（TC-5.14，见 §10）

同一 `(hostId, sessionId)`，PC 桌面端与手机 App 同时截取事件序列并比对。

### 6.4 明确"不一致"的白名单

写进 `02` 产品承诺，**只有以下差异属预期**：

- 三栏桌面 vs 单栏手机的**布局**
- PC `dsh.client` 设置页 / 侧栏按钮（手机没有对应入口）
- 事件到达的短暂延迟（P95：局域网 <300ms、跨网 <800ms）与断线补齐窗口

**其余任何差异都是缺陷。** 这条比 v2.0 更严，因为不再有"原生插槽降级"这类可解释的豁免。

## 7. Termux 本机引擎怎么处理

**保留双主机模型（D-002 不推翻）**，但手机侧瘦身：

| 项 | 变化 |
|---|---|
| Termux 里的 DSH | **原版 `dsh web` 即可**，不安装 `dsh-wb-cloud-sync` |
| 手机插件管理 / 插件页 / 「仅当前主机」标注 | **删除** |
| App 如何拿到本机会话 | `client-core` 直连 `127.0.0.1:3080` 的 DSH Web API，自己渲染 |
| 索引上报 | 本机档案下由 **App** 直接向 CP 上报摘要（或离线时不报，仅本地展示） |
| launch token / 回环 / 前台服务 / 安全模式 | **全部保留**，与插件无关 |
| `engines.dsh` / 双端 commit 校验 | 保留（App 渲染器仍需与 DSH 事件格式对齐） |

> 结果：Termux 侧从"我们的插件宿主"变成"纯 Agent 运行时"，安装引导少一步，坏插件把引擎搞挂的概率大幅下降，安全模式触发条件收敛为 DSH 自身启动失败。

## 9. 收益与代价

**收益**
- 手机侧攻击面归零：不执行插件代码、无清单注入、无提权路径（`08` 中三类威胁直接消失）
- 包更薄：无 Cordis 客户端半边、无桥接、无插件管理器
- Android / iOS 共用同一份 `client-core` + `Renderer`，两端视图天生一致
- PC 插件成为唯一扩展点，版本矩阵从「双端 × commit」简化为「PC × commit + App × renderContract」
- Termux 只是原版 DSH，升级与排障更简单

**代价（必须认）**
- 失去「同一套官方 Web UI」的同源保证 → 新增 **R-29**（渲染器漂移，值 16，红）
- 需长期维护 Golden Fixture 与渲染契约版本；DSH 上游新增事件类型时，App 必须跟进
- 原本由官方 Web UI 免费提供的界面能力（会话标题生成展示、复杂工具渲染等）要自己实现
- 手机端不再能"装第三方插件扩展 UI"——这是产品定位变化，需写进 `01` 非目标

## 12. ADR-013 全文（插入 `03` §8）

### ADR-013 手机侧能力 App 内置，不做 dsh 插件（取代 ADR-011、修订 ADR-012）
- **状态**：已接受（D-003）
- **决策**：PC 侧保留 `dsh-wb-cloud-sync` 作为**唯一插件**；手机侧不引入 Cordis、不装 bundle、不注 slots，全部能力以 `client-core` + `Renderer` 形式内置于 App；Termux 只跑原版 `dsh web`；工具卡改为协议内置卡片。
- **理由**：手机侧不再需要"可插拔 UI"这一产品能力，却要为此承担桥接、清单校验、提权面与双端插件版本矩阵；收敛后攻击面归零、Android/iOS 可共用渲染器、PC 插件成为单一扩展点。
- **取代/修订**：**取代 ADR-011**（插件归属主机 + 工具卡是唯一跨主机 UI）；**修订 ADR-012**（WebView 套壳改为 App 自研渲染器，Kotlin 平台层与 launch token 链路保留）。
- **后果**：失去"同一套官方 Web UI"的同源一致性保证 → 必须引入 §4.1 渲染一致性契约、`renderContract` 版本、Golden Fixture 与 TC-5.14；新增 R-29；手机端不再支持第三方插件扩展 UI（写入 `01` 非目标）。
- **不推翻**：ADR-007（双主机 / 多真源）、ADR-008（显式选择不迁移）、ADR-009（Termux 优先 / Android only）、ADR-010（双端 commit）全部继续有效。

## 13. 产品承诺文案（写入 `02` §5）

> **切换到电脑端后，手机 App 显示的会话内容与电脑端一致**：消息文本与顺序、工具调用与结果、产物、审批、状态点、置顶与工作空间，均以该电脑的会话日志为唯一来源。
>
> 因宿主不同，**界面布局、PC 专属设置入口、以及短暂的网络延迟与断线补齐窗口**属预期差异；除此之外任何内容差异均为缺陷。手机端不安装 dsh 插件，界面能力由 App 内置实现。
