## 2. 红色风险专项应对

### R-19 Termux 保活（**新增最高频风险**）
- **预防**：前台服务 + 常驻通知 + 电池优化引导 + 最近任务锁定；逐档适配 vivo/小米/华为/荣耀/OPPO。
- **监测**：引擎存活心跳、被杀次数、温度与内存打点；三档真机 30min 长稳。
- **应急**：被杀 10s 内提示并直达放行设置；连续失败进安全模式；长任务引导切换远程档案。
- **兜底**：产品**不承诺**后台永久存活；文档明确「直达设置 ≠ 一定放行」。低配机默认推荐远程主机。

### R-20 双端 commit 漂移
- 双端 `pinned-commit.txt` + `HostProfile.dshCommit` 上报 + `COMMIT_DRIFT` 拒绝合并。
- Termux 安装时校验 `engines.dsh`；升级只走里程碑窗口 + 双端全量回归。
- 应急：阻断该主机索引，提示用户重跑安装引导，**不允许带病合并**。

### R-21 / R-22 主机心智模型与命名空间（**v2 特有的产品+技术双风险**）
- R-21 靠预期管理：首次引导、切换确认弹窗、顶部执行位置常驻、索引按 hostId 分组。
- R-22 靠架构约束：所有键（索引/幂等/游标/租约）带 hostId，错投即 409；混沌专项用例 TC-1.9/1.10/TC-4.3。
- 这两项若在 M2 门禁失败，**不得进入 P3**。

### R-01 / R-02 / R-06（沿用 v1，R-01 升级为双端）
- R-01：双端锁 commit，Spike 覆盖 PC 与 Termux 两侧接缝。
- R-02：W1 Spike 三问（事件订阅 / 不打开写句柄能否提交 / 只读枚举回放），任一不过当天上报发起人。
- R-06：架构必然代价，以预期管理为主，做成首次连接四项检查清单。

## 4. 上报规则

- 红色风险状态变化 **24 小时内**上报发起人。
- 风险值 ≥15 且缓解失效 → 立即暂停对应模块合入，PM 召集决策会。
- **主机模型相关争议（是否迁移、是否加第四档案）一律上报发起人**，不在研发层自行决定。
- 所有新识别风险当日入表，不允许"先记在群里"。
