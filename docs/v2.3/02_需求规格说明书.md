## 3. 功能需求

### FR-1 主机档案与切换（v2 新增，P0 基础）

- FR-1.1 App 内置三种主机档案：`on-device`（Termux 本机引擎）、`ssh`（端口转发到 PC）、`relay`（跨网中继）。
- FR-1.2 顶部常驻**当前执行位置**标识（主机名 + 类型 + 在线状态），切换必须用户显式确认。
- FR-1.3 切换时弹出提示：「切换主机不会带走会话、文件与插件」；确认后重建客户端连接、清空当前会话视图。
- FR-1.4 每台主机档案独立保存地址、令牌、`dshCommit`、能力标签；多主机是纯客户端能力，协议无需扩展。
- FR-1.5 `hostId` 全局唯一且稳定；`SessionIndex` 主键为 `(hostId, sessionId)`，禁止跨主机合并同名会话。
- FR-1.6 CP 维护主机注册表：`hostId / kind / deviceName / platform / dshCommit / capabilities / state / lastSeenAt`。

### FR-2 本机引擎（Termux，v2 新增，P1 核心）

- FR-2.1 首次启动引导：从 F-Droid / GitHub Releases 装 Termux → `pkg update && pkg upgrade` → `pkg install nodejs git` → 安装与 `pinned-commit.txt` 一致的 DSH。
- FR-2.2 App 拉起 `dsh web --host 127.0.0.1 --port 3080 --no-open`，从 stdout 解析一次性 launch token，WebView 用 token 换 cookie。
- FR-2.3 本地服务**只绑回环**；HTTP 客户端覆盖 Host 头、不带 Origin，防止同机其他网页访问。
- FR-2.4 引擎状态可见：启动中 / 运行中 / 安全模式 / 失败；连续两次启动失败自动进入**安全模式（不加载插件）**，用户可修配置后恢复。
- FR-2.5 前台服务 + 常驻通知保活；检测到被系统杀掉后提醒并直达对应品牌（vivo/小米/华为/荣耀/OPPO）省电策略放行设置。
- FR-2.6 发热 / 耗电 / 存储（约 1GB）在使用前明示；长任务提示接电源或改用远程主机。
- FR-2.7 模型凭据只存手机本地，由用户在 App 内录入；模型请求走用户配置的提供方并联网计费，产品内说清「本机运行 ≠ 本地推理」。
- FR-2.8 引擎重置会清空本机会话 / 工作区 / 插件 / 设置，必须二次确认并提示先导出。

### FR-3 手机侧 App 内置客户端（**v2.3 / D-005 重写**）

> 手机侧**不做 dsh 插件、不写 UI、不写皮肤**：无 Cordis、无 `apply(ctx)`、无 bundle、无 slots、无 UI 源码、无渲染器。Termux 只跑原版 `dsh web`（锁 v0.2.2-rc.1）。完整方案见 `13`。

- FR-3.1 `client-core`：纯协议客户端，不依赖 UI 框架、**不给 UI 供数**；覆盖 CP REST、Relay WS、SSH/回环 HTTP 三档案；负责帧重组（≤64KiB 保序）、`sinceSeq` 补齐、`clientMsgId` 幂等、Cursor 与错误码映射；服务 App 壳的索引 / 状态点 / 切换。
- FR-3.2 **界面由官方 `dsh web` 提供**：三档案 WebView 直接寻址同一官方服务（本机 `:3080` / SSH `:3081` / Relay HTTP·WS 反代）；窄屏适配由官方内置，我们不做任何 CSS、slots 注入或自定义组件。
- FR-3.3 协议内置卡片（`wbsync/card`，`kind` 封闭枚举）随 `SessionEvent` 落日志，由官方 UI 侧呈现；服务端校验 Schema，**不执行任何插件代码**。
- FR-3.4 `HostSwitcher` + **Kotlin 原生页面**：三档案切换 + 「不带走会话/文件」确认 + 当前执行位置常驻；配对页、PC 离线页为原生页面（非 Web UI 皮肤）。
- FR-3.5 Android 与 **iOS PWA 共用同一份 `client-core`** 且都打开官方 `dsh web`，两端界面天生一致；iOS 仅开放 `ssh` / `relay`。
- FR-3.6 **不装第三方窄屏适配插件**；安装校验须拒绝或提示冲突，避免与官方适配叠加。
- FR-3.7 **不做** `rendererVersion` / `renderContract` / Golden Fixture / 视图快照 / UI 哈希；一致性由「同一个官方 Web UI」天然保证，唯一版本约束是双端 `pinned-commit.txt`。
- FR-3.8 W1 与 W15 必须跑**官方窄屏冒烟**（TC-5.20）：Android Chrome / iOS Safari，390px 竖屏，三档案可用；官方在窄屏下主动取舍的功能属预期，不记缺陷。

### FR-4 远程链路（沿用 v1，P0）

- FR-4.1 同 OAuth 账号自动发现在线主机；配对码 6 位、10min TTL、设备+IP 限速 5 次/分 → 一次性挑战 60s → HMAC-SHA256 → 设备令牌。
- FR-4.2 令牌仅存 SHA-256 摘要；单设备 1 个活跃令牌；静默重连；吊销写墓碑，重启不复活。
- FR-4.3 Relay 只做帧透传（≤64KiB，帧序即流序），host 离线立即 409，10s 无进度防悬挂。
- FR-4.4 SSH 档案走 `ssh -L 3081:127.0.0.1:3080`，填入远程 `dsh web` 打印的 token，cookie 默认 30 天，远程重启后需重新配对。
- FR-4.5 PC 需显式开启「允许移动端连接此设备」+「保持唤醒」；离线时新建工作空间入口置灰。

### FR-5 会话索引与事件流

- FR-5.1 Host 启动时全量上报本地会话索引，之后增量；字段含 `hostId / sessionId / workspace / title / pinned / state / lastSeq / lastActiveAt / headerRef`。**不含事件正文**。
- FR-5.2 `state` 四态：运行中（蓝）、待审批（琥珀）、已完成一轮（绿，打开即清零）、不可读（红）。
- FR-5.3 事件透传**原样携带会话内 `seq`**，不自编号；未知类型带 `ignorable: true` 时跳过。
- FR-5.4 手机端按 Surface 四类渲染；`assistant/chunk` 折叠成完整消息；`tool/call` 与 `tool/result` 按 `callId` 配对。
- FR-5.5 断线重连按 `sinceSeq` 补齐连续前缀，禁止时间戳做游标；客户端幂等丢弃 `seq <= sinceSeq`。
- FR-5.6 `session/prompt` 带 `clientMsgId` 幂等；手机**永不自开写句柄**，写入交该主机的会话 owner。
- FR-5.7 执行中消息进队列、共享上下文、按序处理；「停止」走独立 `session/cancel`；崩溃悬空轮次由 DSH resume 合成 `interrupted`，我们不自修日志。
- FR-5.8 「新开任务 = 全新会话」，不继承上一任务上下文。

### FR-6 审批 / 产物 / 附件 / 定时任务

- FR-6.1 `$events` 转发审批、提问、计划评审，桌面端与手机端先答先得；琥珀点是阻塞，答完才清。
- FR-6.2 产物以工具卡形式回传，支持预览、列表、批量保存分享、导出 PDF/DOCX/MD。
- FR-6.3 手机拍照 / 选文件发给当前主机，落盘到**该主机**工作区；远程 Relay 链路仅图片附件。
- FR-6.4 定时任务定义与账号绑定，由**选中的那台主机**执行；切换主机后任务列表按 `hostId` 分组展示。
- FR-6.5 置顶顺序、工作空间移除、设备名同步沿用 v1；置顶与调序仅 PC 端可写。

## 5. 关键业务规则

- **BR-1 会话跟随执行位置**：不跟账号走、不跟 App 走，跟 `hostId` 走。
- **BR-2 每主机内单写者**：跨主机靠命名空间隔离，不靠锁。
- **BR-3 切换主机不迁移**：会话、文件、插件、定时任务都留在原主机。
- **BR-4 插件可见性**：装在哪台主机，只增强哪台主机；工具卡是唯一跨主机 UI 扩展。
- **BR-5 同账号 ≠ 同数据**：账号只同步设置 / Memory / 自动化定义 / 主机注册表。
- **BR-6 本机运行 ≠ 本地推理**：模型仍在云端提供方，按用户账号计费。
- **BR-7 默认最小权限**：手机可控端点由 `allowedEndpoints` 白名单限制。
- **BR-8（v2.3）手机侧不装插件、不写 UI**：界面由官方 `dsh web` 提供；`client-core` 只服务 App 壳，不供数、不解析、不渲染。官方窄屏下主动取舍的功能属预期，不记缺陷。

### ★ 产品承诺：切换到电脑端后的视图一致性

> **手机端界面 = 官方 `dsh web` 在当前 DSH 版本下的窄屏原生呈现。**
>
> 本机、SSH、Relay 三种档案下，手机 WebView 打开的都是同一套官方 Web UI；切换到电脑端后，**界面样式与功能保持与手机端一致，会话内容来自该电脑的 `~/.dsh` 日志，为唯一数据源**。
>
> 我们不提供自定义气泡、自定义卡片或自定义移动皮肤；官方未提供或官方在窄屏下取舍的功能，以官方实际呈现为准，**不作为缺陷**。预期差异仅限：与 PC 桌面端的布局差异、PC 专属设置入口、短暂网络延迟与断线补齐窗口、以及由 carrier 显式声明并提示的链路能力限制。

验收依据：`07` TC-5.14 内容对拍 / TC-5.19 原生离线页 / **TC-5.20 官方窄屏冒烟 / TC-5.21 皮肤冲突检查** + `03` §4.5 白名单。**不需要**样式快照、UI 哈希校验或 Golden Fixture。最终方案见 `13_官方原生UI收口修订单.md`。

> BR-8（v2.3 修订）：手机侧不装插件、不自研事件解析、**不写任何 UI 规则**；业务差异只出现在 `DshCarrier`，界面完全由官方 `dsh web` 提供。

## 6. 验收标准

### M1（W6，远程闭环）

1. 同账号手机自动发现 1 台在线 PC，配对成功。
2. 手机发文本 → PC 同一会话出现，PC 回复实时回手机。
3. 拔网 10s 恢复，不丢不重；同一 `clientMsgId` 重发 5 次只产生 1 条 `user/message`。
4. PC 执行中手机连发 3 条，全进队列且按序处理。
5. 卸载 PC 插件后 `/__wbsync/*` 全 404，无残留。

### **M2（W10，本机引擎）★ 新增**

6. 真 Android 机按引导装好 Termux + nodejs + DSH，冷启动 ≤5s。
7. WebView 用 launch token 换 cookie 成功；`127.0.0.1:3080` 仅回环可达，同机其他网页访问被拒。
8. **三档案 WebView 都打开同一个官方 `dsh web`**，390px 竖屏窄屏冒烟通过（软键盘 / 抽屉 / 设置页 / 宽表格 / 发送后收起键盘）；**未安装任何第三方窄屏适配插件**；官方在窄屏下主动取舍的功能属预期。
9. 前台保活 30min 不被杀；手动杀掉后 App 10s 内提示并跳转省电设置。
10. 连续两次启动失败自动进安全模式，修好后可恢复且不丢会话。
11. 三档案切换：本机 → SSH → Relay → 本机，会话列表按 `hostId` 正确隔离，0 次串会话。
12. 切换时提示「不带走会话与文件」必现。

### M3（W13，完整体验）

13. 两台 PC + 两 Android + 一 iOS，主机状态点正确；iOS 用 PWA 能发消息 / 看产物 / 批审批。
14. 工具卡在本机 / SSH / Relay 三链路渲染一致；无桥接时降级为工具卡而非静默消失。
15. 产物卡预览并导出三种格式；审批手机作答后任务继续。
16. 置顶顺序、工作空间移除、设备改名同步一致；Host 离线立即 409 不悬挂。

### M4（W16，GA）

17. 安全审计无高危；出网审计 0 字节文件、0 条会话正文、0 条 launch token 日志。
18. 混沌 200 次随机断连补齐 100%；性能达 NFR-1。
19. 三平台 PC + 三档 Android + iOS PWA 冒烟通过；双端 `pinned-commit.txt` 一致。
20. 文档齐全，第三方按 PROTOCOL 可在 1 天内写出最小客户端。
