## 0. 事实依据

DeepSeek Harness **v0.2.2-rc.1**（2026-11-04 发布，npm `latest` / `next` 均指向该版本）已把移动端可用性做成**官方内置能力**：软键盘收起与光标滚动、窄屏布局、菜单与操作入口在窄屏下可用、设置页全屏 + 横向导航、触屏输入 16px 防 iOS 缩放、宽 Markdown 表格局部横滚、触屏动作不被 hover 提示阻挡、聊天引用与紧凑预览、步骤收起保留全部助手文字。同系列 v0.2.2-alpha.2 已把 Node 下限提到 **24.9**，与 `06` 环境基线一致。

此前参考的 `dsh-client-ui-mobile` / `dsh-pocket-ui` / `dsh-mobile` 等是**针对 0.1.x / 0.2.1 的 additive 皮肤插件**；官方补齐后不再需要。这些插件自己也声明"不能改组件内部""上游大版本升级需跟随更新""不要与其他窄屏适配插件同时开"。

> ⚠ 该版本仍是 **rc**：官方明确"行为还在收敛，适合测试 profile 先跑，别直接盖到每天干活的入口"。因此本项目 **`pinned-commit.txt` 锁到 v0.2.2-rc.1 对应 commit**，生产升级单开 ADR。

## 1. 最终形态（v2.3）

```
手机 App（薄壳，无 UI 源码）
├─ Kotlin 平台层：主机切换器 / 配对页 / Keystore / 前台服务 / 离线页
├─ client-core：DshCarrier×3 + DshMux（服务 App 壳，不给 UI 供数）
└─ WebView ──▶ 直接打开【官方 dsh web】
                 on-device : http://127.0.0.1:3080
                 ssh       : http://127.0.0.1:3081（SSH 隧道）
                 relay     : Relay 反向代理到该 Host 的 dsh web

PC：DSH + dsh-wb-cloud-sync（唯一插件）
  apply(ctx)：事件透传 / 幂等 / Route / 索引上报
  ctx.webServer：/__wbsync/*（状态 / 配置 / 配对 / 产物票）
  dsh.client 半边：仅桌面设置页（允许连接、保持唤醒、配对码、HOST_TOKEN）
                   ❌ 不再托管任何 UI 资源

手机 Termux（真源 A）：原版 dsh web，零插件
```

**一致性结论**：三档案下手机打开的**都是同一个官方 `dsh web`**，UI 根本不在我们仓库里。因此「切到电脑端仍是同一界面」不需要任何契约、哈希、Fixture 去兜——天然成立。项目里剩下的唯一版本约束是双端 `pinned-commit.txt` + `COMMIT_DRIFT`。

**官方补丁的边界**（产物仍需要 App 补）：官方做的是「让网页在小屏上能用」，是响应式 Web，**没有通知、没有后台、断网界面打不开、复杂多面板仍会取舍**。这正是 `android-shell` 的前台服务与保活存在的理由。

## 3. 仍然要写的四块（都不是 UI 规则）

1. **PC 唯一插件**：事件透传、幂等、Route 校验、索引上报、配对、桌面设置页。
2. **CP + Relay**：OAuth、HostRegistry、`(hostId, sessionId)` 索引、Cursor、幂等表、帧透传。
3. **client-core**：`DshCarrier`×3 + `DshMux`（只服务 App 壳：主机切换、配对、索引、状态点、保活；**不再给 UI 供数**）。
4. **Android 壳**：WebView 三档案寻址、前台服务与省电放行、launch token 换 cookie、**原生页面**（主机切换器 / 配对页 / PC 离线页）。

> 这四块与「官方 UI」正交，不受 v0.2.2-rc.1 影响。

## 5. 产品承诺（最终文案，覆盖 `02` §5 / `11b` §7）

> **手机端界面 = 官方 `dsh web` 在当前 DSH 版本下的窄屏原生呈现。**
>
> 本机、SSH、Relay 三种档案下，手机 WebView 打开的都是同一套官方 Web UI；切换到电脑端后，**界面样式与功能保持与手机端一致，会话内容来自该电脑的 `~/.dsh` 日志，为唯一数据源**。
>
> 我们不提供自定义气泡、自定义卡片或自定义移动皮肤；官方未提供或官方在窄屏下取舍的功能，以官方实际呈现为准，不作为缺陷。预期差异仅限：与 PC 桌面端的布局差异、PC 专属设置入口、短暂网络延迟与断线补齐窗口、以及由 carrier 显式声明并提示的链路能力限制。

## 7. ADR-015 官方原生 UI，零皮肤（插入 `03` §8）

- **状态**：已接受（D-005，2026-11-13）
- **决策**：手机界面完全采用官方 `dsh web` 的窄屏原生呈现；不写自定义 UI、不写移动皮肤、不托管 UI 静态资源、不装第三方适配插件；三档案的 WebView 都直接寻址官方 `dsh web`。
- **理由**：v0.2.2-rc.1 已内置移动端适配；自写皮肤只增加上游跟随成本且与官方冲突；去掉 UI 层后一致性天然成立、协议字段与测试用例大幅收敛。
- **取代**：取代 ADR-014 的「ui-bundle 双投放 / 皮肤层」全部条款；ADR-014 的 Carrier 抽象、能力声明下沉、TOFU / pin、PC 唯一插件继续有效。取代 ADR-013 的「App 内置 UI」条款。
- **后果**：删除本文 §2 的全部字段/包/用例；`pinned-commit.txt` 锁 v0.2.2-rc.1；W1 增加官方窄屏冒烟；W15 上游回归加厚；周期保持 16 周。
- **不推翻**：ADR-007~012、以及 D-004 的四条社区借鉴（B1–B4）全部继续有效。
