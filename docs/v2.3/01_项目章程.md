## 1. 背景与变更理由

v1.0 把手机定义为「纯 PWA 投影」，交付物里手机端不是 dsh 插件。负责人复审后认为这浪费了 DSH「一切皆插件」的核心价值：**手机端应该也能装插件、注 slots、跑自己的 Cordis 宿主**。

技术路径已验证可行：Android 上用 Termux 装 nodejs，`npx @deepseek-ai/dsh web` 起在 `127.0.0.1:3080`，套壳 WebView 打开即可，无需 Root、无需 PRoot 打包 ~1GB rootfs。这比社区 dsh-Go 的本机引擎轻一个量级。

**但这一步的代价必须写进章程**：手机里有了第二个 `~/.dsh`，会话、插件、工作区就分了家。v1 的「全局一个真源」不再成立，项目定义从「同一会话多视图」变成**「多主机选择器」**——这正是 dsh-Go 要做本机 / SSH / Remote 三个主机档案的原因：对话和插件归各自主机管理，切换主机并不会自动同步文件与会话。

同时保留 WorkBuddy 式「连电脑看同一会话」能力，作为三种主机档案之一，v1 的 P1 成果全部复用。

## 2. 项目目标

见 `00_项目总览.md` G1–G7。补充组织级目标：

- G8 交付物可开源、可自托管，用户不信任我们的服务器也能跑通远程链路；本机引擎链路完全不经过我们的服务器。
- G9 所有扩展通过 DSH 官方插件接缝完成，**不 fork、不打补丁改内核**；手机宿主与 PC 宿主共用同一套插件规范。
- G10 形成 `PROTOCOL.md`，第三方客户端可按主机档案接入任意主机。

## 3. 范围边界

### In Scope

- **Android 套壳 App**：WebView + Kotlin 平台层（前台服务、常驻通知、省电策略放行引导、电池优化、发热提示）。
- **Termux 运行时**：安装引导、Node/DSH 版本管理、`dsh web` 拉起与停止、launch token → cookie、回环绑定校验。
- **主机切换器**：本机引擎 / SSH 主机 / Relay 主机三档案，当前执行位置常驻可见。
- **★ 手机侧 App 内置客户端**（D-003 + D-005）：`client-core`（Carrier×3 + Mux）+ **Kotlin 原生页面**（主机切换器 / 配对页 / PC 离线页）；**不做 dsh 插件、不写 UI、不写皮肤**；界面由官方 `dsh web` 提供，Termux 只跑原版 DSH。PC 侧 `dsh-wb-cloud-sync` 是唯一插件。
- PC Host 插件、Relay、CP、会话索引（`hostId` 命名空间）、工具卡跨主机渲染。
- 账号级设置 / Memory / 自动化同步；产物、审批、附件、定时任务、队列语义。
- 文档、部署手册、安全设计、真机测试矩阵。

### Out of Scope

- **主机间会话 / 文件 / 插件迁移**（v2 核心边界）。
- **iOS 本机引擎**：iOS 仅 PWA 远程视图，不跑 DSH。
- 云端执行 / 云端沙箱 / 会话正文上云。
- PRoot 打包 APK、完整 Linux rootfs、Google Play 上架。
- 多人协作编辑同一会话、IM 助理渠道、DSH 内核修改。
- **★ 自定义手机 UI / 移动皮肤 / UI 静态资源托管 / 视图快照对拍**（v2.3 / D-005）。
- **★ 安装第三方窄屏适配插件**（与官方适配互斥）；以及「能力随模式衰减」。

## 4. 关键假设与约束

| 编号 | 假设 / 约束 | 若不成立的应对 |
|---|---|---|
| A1 | Termux（F-Droid / GitHub Releases 官方渠道）可在目标 Android 上装 nodejs 并跑通 `dsh web` | W1 Spike 真机验证；失败则启用兼容启动 / 降级为纯远程模式并公告 |
| A2 | `dsh web` 的 launch token → cookie 链路可被 WebView 正确消费；只绑回环 | W1 Spike 验证；需覆盖 Host 头、不带 Origin |
| A3 | WebView 能加载 `dsh.client` slots 注入的组件 | W1 Spike 验证；不满足则本机插件只保留 host 半边 + 工具卡 |
| A4 | 每主机内单写者；跨主机靠 `hostId` 隔离 | 索引合并时校验命名空间，冲突拒绝 |
| A5 | PC 与 Termux 锁同一 DSH commit | CI 双端校验；漂移即阻断发布 |
| A6 | Android 前台服务 + 用户手动放行省电策略可维持 30min 引擎 | 产品层显式引导；发热/耗电给提示，不承诺后台永久存活 |
| A7 | DSH Developer Preview 会有不兼容变更 | 全项目锁 commit；升级单独立 ADR |
| A8 | Relay/CP 可自托管 | docker-compose 一键起；本机引擎链路不依赖它 |

- **ADR**：协议字段、信任边界、存储选型、主机模型必须写 ADR。v2 新增 ADR-007~012，并显式标注对 ADR-001/003/006 的取代关系。
- **接口变更**：`04` 是唯一契约源，字段变更同步文档 + 版本号 + CHANGELOG。
- **范围变更**：变更单 > 3 人日上报发起人。
- **冲突升级**：技术路线 → 架构师；跨端体验 → PM；安全 → 安全 Owner 一票否决；**主机模型争议 → 发起人裁定**。

## 8. 验收与发布策略

- **DoD**：代码合入 + 单测 + 协议文档同步 + E2E + CHANGELOG + 至少 1 人 Review；涉及 Termux 的 PR 需真机截图/录屏佐证。
- **发布节奏**：内测 10 人（W6）→ 封闭灰度 20 人（W12）→ 开源 GA（W16）。
- **分发**：APK 走侧载（Termux 亦需用户自行从官方渠道安装），不上 Play；npm bundle 走 `--provenance`。
- **回滚**：组件独立版本；APK 签名必须固定，避免升级时卸载清空 Termux 环境。
