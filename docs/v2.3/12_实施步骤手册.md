## 3. P0 · W1–W2 重设计与 Spike

### S-1.1 Re-Kickoff 与方案对齐
- **时机**：W1 D1 ｜ **Owner**：PM + ARC
- **动作**：全员过一遍 `13` 的最终形态图；明确三件事：**PC 是唯一插件点**、**手机不装插件也不写任何 UI**、**三档案 WebView 都打开同一个官方 `dsh web`**；基线锁 v0.2.2-rc.1
- **产出**：会议纪要回写 `03` §4.5
- **验收**：每人能说清「切到电脑端为什么界面不用我们管」
- **坑**：不要再出现「手机宿主插件」「slots 注入」「ui-bundle / 投放点 / 皮肤」这类 v2.0–v2.2 残留说法

### S-1.2 ★ Spike A：Termux 全链路（P0 硬门禁）
- **时机**：W1 D1–D3 ｜ **Owner**：RUN + AND，ARC 判定
- **输入**：中档 Android 真机、Termux（F-Droid/GitHub Releases）
- **动作**：
  1. `pkg update && pkg upgrade && pkg install nodejs git`
  2. 安装 `pinned-commit.txt` 对应 DSH，校验 `node -v` 满足 engines
  3. 起 `dsh web --host 127.0.0.1 --port 3080 --no-open`
  4. 从 stdout 解析一次性 launch token
  5. WebView 打开 `http://127.0.0.1:3080/?token=…` 换 cookie
  6. 覆盖 Host 头、不带 Origin；验证同机浏览器访问被拒
  7. **WebView 加载官方 `dsh web` 窄屏 UI**，390px 竖屏冒烟：软键盘不遮挡输入框、侧栏可开合、设置页可用、宽表格局部横滚
  8. 确认未安装任何第三方窄屏适配插件；记录冷启动耗时
- **产出**：`spike-a-report.md` + 录屏
- **验收**：八步全通、冷启动 ≤5s、**只绑回环**、token 不落日志
- **坑**：DSH 刻意拒绝 `--host 0.0.0.0`；cookie 绑主机名，`localhost` 与 `127.0.0.1` 不能混用

### S-1.3 ★ Spike B：SSH / Relay 直连官方 `dsh web`（P0 硬门禁）
- **时机**：W1 D2–D4 ｜ **Owner**：HE-PC + BE-RL + AND
- **输入**：一台 PC、DSH web profile、一台 Android 真机
- **动作**：① PC 起官方 `dsh web`（只绑回环）；② 手机经 SSH `-L 127.0.0.1:3081:127.0.0.1:3080` 隧道打开 `http://127.0.0.1:3081`；③ 经最小 Relay HTTP·WS 反代打开同一服务；④ 三档案都做 390px 窄屏冒烟；⑤ PC 插件只注册 `/__wbsync/status`，**不注册任何 UI 路由**
- **产出**：`spike-b-report.md` + 三档案录屏
- **验收**：三档案打开的都是**同一个官方 Web UI**；窄屏可用；插件卸载后 `/__wbsync/*` 全 404、无残留注册
- **坑**：DSH 刻意拒绝 `--host 0.0.0.0`；`Host` 头是回环权限凭据，cookie 绑主机名（`localhost` 与 `127.0.0.1` 不可混用）；**不要试图给官方 UI 加任何 CSS/皮肤**

### S-1.4 ★ Spike C：宿主提交入口（P0 硬门禁）
- **时机**：W1 D2–D4 ｜ **Owner**：HE-PC + ARC
- **动作**：回答三问并留可运行证据：① 能否订阅带连续 `seq` 的会话事件？② **能否在不打开写句柄的前提下把一条用户消息交给当前轮次 owner？** ③ `sessionPersistence.list()` / `open(id,'read')` 能否枚举与只读回放？
- **产出**：`spike-c-report.md`
- **验收**：三问全过才进 P1；任一不过当天上报发起人，启动上游 issue / 收缩为只读镜像
- **坑**：**严禁自开 `open(id,'write')` 绕过单写者**，第二个写句柄会抛 `SessionAlreadyOwnedError`

### S-1.5 锁定双端 commit
- **时机**：W1 D4 ｜ **Owner**：HE-PC + RUN
- **动作**：写 `pinned-commit.txt`；CI 加双端一致性校验；Termux 安装脚本读同一文件
- **产出**：`pinned-commit.txt`、CI 检查
- **验收**：PC 与 Termux 报同一 commit，不一致即 CI 红
- **坑**：社区脚手架 engines 口径与官方略有差异，统一按 Node 24.9+ 对齐

### S-1.6 环境基线固化
