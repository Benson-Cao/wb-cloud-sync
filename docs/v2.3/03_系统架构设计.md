## 1. 架构原则

| 编号 | 原则 | v2 含义 |
|---|---|---|
| P1 | **多个真源、显式选主机、每主机内单写者** | 手机 Termux `~/.dsh` 与每台 PC `~/.dsh` 各自是真源；`hostId` 命名空间隔离 |
| P2 | **执行留在主机** | 云不做 Agent、不跑模型、不存工作区；本机引擎链路完全不经我们的服务器 |
| P3 | **云只管索引与路由** | CP 存账号 / 主机注册表 / SessionIndex / Cursor，不存事件正文 |
| P4 | **PC 主动外连，手机本机直连回环** | PC 零入站；手机本机引擎只绑 `127.0.0.1` |
| P5 | **协议优于实现** | Relay 只做帧透传；工具卡是跨主机 UI 的唯一契约 |
| P6 | **不 fork DSH** | 两端宿主共用同一套 Cordis 插件规范 |
| P7 | **可逆副作用** | 路由、监听、定时器、WS、前台服务一律可撤销 |
| ★ P8 | **插件归属主机** | 装在哪台 profile 就只增强哪台；跨主机只认工具卡 |
| ★ P9 | **双端同 commit** | 事件格式版本化，commit 漂移即拒绝索引合并 |

## 2. 总体架构（双主机）

```
                    ┌──────────────────────────────┐
                    │ 云端控制面 CP                 │
                    │  OAuth / 设置 / Memory / 自动化│
                    │  HostRegistry(hostId,kind,   │
                    │    dshCommit,state,caps)      │
                    │  SessionIndex(hostId,sessionId)│
                    │  Cursor / Idempotency          │
                    └───────┬──────────────┬───────┘
                            │ 索引/注册     │ 令牌校验
                    ┌───────▼──────────────▼───────┐
                    │ Relay（仅远程档案需要）        │
                    │  /pair  /d/<hostId>/*  /ws     │
                    └───────┬───────────────────────┘
                            │ WSS（PC 主动注册）
        ┌───────────────────┼────────────────────┐
        ▼                   ▼                    ▼
┌────────────────┐  ┌──────────────┐  ┌────────────────────────┐
│ PC-A / PC-B    │  │ SSH 主机     │  │ Android 手机（App）     │
│ DSH web profile│  │ ssh -L 3081  │  │ ┌────────────────────┐  │
│ + wb-cloud-sync│  │ → PC DSH     │  │ │ WebView 套壳        │  │
│ ~/.dsh 真源    │  └──────────────┘  │ │  + 主机切换器       │  │
└────────────────┘                    │ └──────────┬─────────┘  │
                                      │ ┌──────────▼─────────┐  │
                                      │ │ Kotlin 平台层       │  │
                                      │ │ 前台服务/通知/放行  │  │
                                      │ └──────────┬─────────┘  │
                                      │ ┌──────────▼─────────┐  │
                                      │ │ Termux 本机引擎     │  │
                                      │ │ node + dsh web      │  │
                                      │ │ 127.0.0.1:3080      │  │
                                      │ │ ~/.dsh（第二真源）  │  │
                                      │ │ + 手机宿主插件      │  │
                                      │ └────────────────────┘  │
                                      └────────────────────────┘
                    iOS：PWA 远程视图（无本机引擎，仅连 PC）
```

**三条链路，用户显式选一条**：

| 档案 | 连接 | 会话真源 | 插件归属 | 经过我们的服务器 |
|---|---|---|---|---|
| `on-device` | WebView → `127.0.0.1:3080` | 手机 `~/.dsh` | 手机 profile | ❌ 否（模型 API 除外） |
| `ssh` | `ssh -L` 转发到 PC | PC `~/.dsh` | PC profile | ❌ 否 |
| `relay` | HTTPS/WSS → Relay → PC | PC `~/.dsh` | PC profile | ✅ 元数据 + 帧 |

## 3. 组件职责

### 3.1 手机 App（Android）

- **WebView 套壳**：加载 `dsh web` 的 Web UI，消费 launch token → cookie；覆盖 Host 头、不带 Origin。
- **主机切换器**：三档案 + 当前执行位置常驻 + 切换确认提示（不带走会话/文件/插件）。
- **Kotlin 平台层**：前台服务、常驻通知、电池优化引导、厂商省电策略直达设置、发热/存储提示、引擎启停与状态机。
- **安全模式**：连续两次启动失败自动不加载插件启动，保留会话，修好后恢复。
- **iOS 降级**：纯 PWA，只提供 `ssh` / `relay` 档案，本机引擎入口隐藏并说明原因。

### 3.2 Termux 运行时

```
pkg update && pkg upgrade
pkg install nodejs git
# 安装与 pinned-commit.txt 一致的 DSH
npx @deepseek-ai/dsh web --host 127.0.0.1 --port 3080 --no-open
```

- stdout 解析一次性 launch token；只绑回环。
- **v2.3：Termux 不安装 `dsh-wb-cloud-sync`，也不装任何窄屏适配插件**；只有原版 DSH，版本由 `pinned-commit.txt` 约束。
- 版本变更需重跑安装并单开 ADR；引擎重置会清空本机会话 / 工作区 / 设置，必须二次确认 + 导出提示。

### 3.3 手机侧 App 客户端（**v2.3 / D-005，无插件、无 UI**）

> 以下原 v2.0「手机宿主插件 / slots / Conversation node / 插件清单」内容**全部废止**；v2.1 的「App 内置 Renderer」与 v2.2 的「UI 双投放」亦已废止，**以 `13`（D-005）为准**。手机侧不引入 Cordis、不装 bundle、不执行插件代码、**不写 UI**；只保留 `client-core`（Carrier×3 + Mux）与三块 Kotlin 原生页面，界面由官方 `dsh web` 提供。PC 插件是唯一扩展点。

**现行职责（v2.3）**：
- `client-core`：只服务 App 壳——主机列表 / 会话索引 / 状态点 / 配对 / 保活；**不给 UI 供数、不解析 `SessionEvent`**。
- `android-shell`：WebView 三档案寻址（本机 `:3080` / SSH `:3081` / Relay 反代）、launch token 换 cookie、前台服务、省电放行。
- **Kotlin 原生页面**：主机切换器 / 配对页 / PC 离线页（非 Web UI 皮肤）。
- **不写**：消息组件、渲染器、CSS、slots、UI 静态资源、视图快照；**不装**第三方窄屏适配插件。

#### ~~3.3 手机宿主插件（bundle）~~〔已废止，保留供对照〕

- 与 PC 插件共用规范：`export const name` / `inject` / `apply(ctx)`、`Schema.object` 配置、`ctx.effect` 可逆。
- `dsh.client` 半边用 `ctx.slots.inject(key, cb)` → `ctx.slots.register({name,id,order}, Component)` 注入 `shell.overlay`、`conversation.session.header.actions`；Conversation node 用稳定 `(kind,id)` 匹配事件族给 Chat 视图加业务行。
- **一个包可同时带 `dsh.client`（Web UI）与手机原生清单**：Web 端与 App 端各渲染各的，DSH Web UI 忽略手机清单。
- **工具卡**：清单 + JSON 视图，随事件下发；视图 ≤32KiB、工具卡 ≤8KiB、合并 ≤4Hz；客户端只渲染 JSON，不执行插件代码。

### 3.4 PC Host 插件 / Relay / CP

沿用 v1 职责，调整两点：
- 所有索引与路由键加 `hostId`。
- Relay 的 `/d/<deviceId>/*` 改为 `/d/<hostId>/*`；本机引擎链路不经 Relay。

## 4. 关键数据流

### 4.1 本机引擎启动

```
App 前台服务 → 拉起 Termux dsh web(127.0.0.1:3080)
 → stdout 解析 launch token
 → WebView 打开 http://127.0.0.1:3080/?token=… 换 cookie
 → **渲染官方 `dsh web` 窄屏 UI**（v0.2.2-rc.1 内置适配，无自定义皮肤）
 → 不加载任何手机侧插件 / slots / UI 资源
 → 引擎状态 = 运行中
```
失败两次 → 安全模式（不加载插件，会话仍在）→ 用户修配置 → 恢复正常模式。

### 4.2 主机切换

```
用户选「公司 Windows (relay)」
 → 弹出确认「切换主机不会带走会话、文件与插件」
 → 断开当前连接（本机引擎可保持后台或按设置停止）
 → 清空会话视图，按 hostId 拉取该主机 SessionIndex
 → 建立新链路（relay 配对态复用 / ssh 转发 / 本机回环）
 → 顶部执行位置更新
```

### 4.3 消息投递（任一主机）

```
客户端 session/prompt {hostId, sessionId, text, clientMsgId}
 → 校验 hostId 与当前链路一致（否则 ROUTE_CONFLICT）
 → 该主机幂等表去重 → 交该主机会话 owner 写入
 → SessionEvent(seq=N) 追加 → 事件流 → 所有订阅该 (hostId,sessionId) 的客户端
 → CP 更新 (hostId,sessionId).lastSeq / state
```

### 4.4 工具卡跨主机

```
插件声明工具卡 → 随 SessionEvent 落进日志（日志是唯一真源）
 → 任一主机、任一客户端读到该事件 → 用自己的组件渲染 JSON 视图
 → 不需要桥接、不需要插件代码在客户端执行
```
这是「手机端可插拔」在远程档案下唯一成立的形态。

## 4.5 ★ 远程档案下的视图一致性边界（v2.3 重写）

> **D-005：官方 `dsh web` v0.2.2-rc.1 已原生适配移动端，本节不再需要任何自定义 UI 契约。**
>
> 形态：三种档案下 WebView 直接寻址**同一个官方 `dsh web`**——本机 `127.0.0.1:3080`、SSH 隧道 `127.0.0.1:3081`、Relay 反代到该 Host 的 `dsh web`。UI 不在我们仓库里，因此切档案后样式与功能**天然一致**；`ui-bundle` / 投放点 A·B / UI 哈希 / `renderContract` / Golden Fixture 全部删除。
>
> App 只保留三块**原生页面**（非 Web UI 皮肤）：主机切换器、配对页、PC 离线页。PC 插件的 `dsh.client` 半边只做桌面设置页，不托管任何 UI 资源。
>
> **官方补丁的边界**：响应式 Web 没有通知、没有后台、断网界面打不开、复杂多面板仍会取舍——这是 `android-shell` 前台服务与保活存在的理由，不是我们要补的 UI 规则。

### 能保证的（数据层，硬保证）

切到 `ssh` / `relay` 后，手机与电脑读的是**同一份 PC `~/.dsh` 事件日志**，且渲染它的是**同一套官方 `dsh web`**。靠三件事锁死：事件原样透传 `seq`、`sinceSeq` 补齐 + `clientMsgId` 幂等、双端 `pinned-commit.txt` 一致。因此消息文本与顺序、工具调用与结果、产物、审批、状态点、置顶与工作空间**一致**。

### 保证方式（v2.3：两层，无需 UI 契约）

| 层 | 机制 | 位置 |
|---|---|---|
| 同源 | 三档案 WebView 都打开官方 `dsh web`；仓库里无 UI 源码 | `06` / `13` |
| 端到端对拍 | 同一 `(hostId, sessionId)` 双端**内容**比对 | `07` TC-5.14 |

### 预期差异白名单（**仅此四项**，其余均为缺陷）

1. 三栏桌面 vs 单栏手机的**布局**差异。
2. PC `dsh.client` 设置页 / 侧栏按钮（手机无对应入口）。
3. 事件到达的短暂延迟（P95 局域网 <300ms、跨网 <800ms）。
4. 断线补齐完成前的短暂缺帧窗口（补齐后必须归零）。

> **v2.3 补充**：官方窄屏下主动取舍的功能（复杂多面板折叠等）**属预期，不记缺陷**；链路能力限制若客观存在，必须由 `DshCarrier` 的 `allowsEndpoint` 显式声明并给文案，不允许静默降级。内容差异仍当缺陷查（TC-5.14）。产品承诺全文见 `13` §5。

## 6. 技术选型（v2 增量）

| 层 | 选型 | 理由 |
|---|---|---|
| 手机运行时 | **Termux + nodejs** | 免 Root、免 PRoot rootfs、约 1GB 以下；官方渠道可装 |
| 手机 UI | **WebView 套壳 + Kotlin 平台层** | 直接复用 `dsh web` Web UI 与 slots，不重写 Flutter 客户端 |
| 本机插件 UI | `dsh-client-ui-slots` / Conversation node | 官方扩展接缝，类型化、可逆 |
| 跨主机 UI | 工具卡（JSON 视图） | 随事件下发，无需桥接，任何主机可渲染 |
| 双端版本 | `pinned-commit.txt` 统一 | 防止事件格式漂移 |
| 分发 | APK 侧载 + npm bundle | Termux 亦由用户自行从官方渠道安装 |

## 7. 备选方案与否决理由

| 方案 | 否决理由 |
|---|---|
| v1 纯 PWA 投影 | 手机端不能装 dsh 插件，浪费「一切皆插件」 |
| PRoot 打包完整 rootfs（dsh-Go 式） | ~1GB、侧载签名、Android 16 直接启动可能被拦、发热；Termux 更轻 |
| 全局单真源 + 手机也写同一会话 | 与「手机跑自己引擎」矛盾；单写者租约会互相拒绝 |
| 自动跨主机同步会话/文件 | 隐私合规不过、成本高，且不是用户要的心智模型 |
| iOS 也跑 DSH | 无成熟 Termux 生态；iOS 降级为 PWA 远程视图 |
| fork DSH 加远程模块 | Developer Preview 频繁变更，维护不可控 |

## 8. 架构决策记录（ADR）

### 状态总览

| ADR | v1 结论 | v2 状态 |
|---|---|---|
| 001 会话真源与写入权 | 全局一个真源 | **已被 007 取代** |
| 002 云端只存元数据 | — | **保留，补充 hostId** |
| 003 Host 主动外连 Relay | — | **修订为「PC 主动外连 + 手机本机回环」** |
| 004 seq 作为唯一游标 | — | **保留** |
| 005 不 fork DSH，锁 commit | — | **保留，扩展为双端同 commit（010）** |
| 006 PWA 优先于原生 App | — | **已被 009 / 012 取代** |

### ADR-007 引入手机本机 DSH 引擎（取代 001）
- **状态**：已接受（D-002）
- **决策**：Android 手机在 Termux 内跑完整 DSH，成为第二台 Host；真源模型改为「每主机一个真源、每主机内单写者」；`hostId` 为命名空间。
- **理由**：让手机端真正成为 dsh 插件宿主；Termux 路径已被验证可行且轻量。
- **后果**：v1「一个会话、多个视图」不再成立；会话索引主键改 `(hostId, sessionId)`；跨主机不共享上下文；RouteLease 作用域缩到主机内。

### ADR-008 主机档案显式选择，不做迁移
- **状态**：已接受
- **决策**：App 提供 `on-device / ssh / relay` 三档案，切换必须用户确认；不迁移会话、文件、插件、定时任务。
- **理由**：dsh-Go 的实测结论——对话和插件归各自主机管理，切换主机并不会自动同步所有文件与会话。与其做半吊子同步，不如把边界说清。
- **后果**：新增切换确认提示、当前执行位置常驻、索引按 hostId 分组；定时任务按 hostId 分组展示。

### ADR-009 Termux 优先于 PRoot 打包 APK；Android only
- **状态**：已接受
- **决策**：本机引擎走 Termux（`pkg install nodejs git` + `dsh web`），不打包完整 Linux rootfs；仅 Android 8.0+/arm64；iOS 降级为 PWA 远程视图。
- **理由**：免 Root、免侧载 rootfs、存储与发热更可控；iOS 目前无成熟 DSH 运行方案，只能用浏览器访问电脑端。
- **后果**：依赖用户自行从 F-Droid / GitHub Releases 装 Termux；APK 仍侧载且签名必须固定；iOS 无本机引擎入口，需在产品内说明。

### ADR-010 双端锁定同一 DSH commit
- **状态**：已接受
- **决策**：`pinned-commit.txt` 同时约束 PC 与 Termux；`HostRegistry.dshCommit` 上报，CP 校验，漂移即拒绝索引合并并提示升级。
- **理由**：DSH 处于 Developer Preview、无 release tag；两端事件格式不一致会导致渲染错乱与索引污染。
- **后果**：Termux 侧 Node 版本需满足该 commit engines；升级单开 ADR + 双端全量回归。

### ADR-011 插件归属主机，工具卡是唯一跨主机 UI 扩展
- **状态**：已接受
- **决策**：插件装在其所属主机 profile，只增强该主机会话；跨主机 UI 只走随 `SessionEvent` 下发的工具卡（JSON 视图，不执行插件代码）。
- **理由**：远程主机没有手机桥接时，原生插槽（胶囊/面板/状态条/消息菜单）不可用，甚至 relay 不转发桥接路径；而工具卡随对话记录下发，任何主机都能显示。
- **后果**：App 插件页标注「仅当前主机」；远程档案下原生插槽降级为工具卡 / web island；限额 ≤32KiB 视图、≤8KiB 卡片、≤4Hz 合并。

### ADR-012 手机 UI 用 WebView 套壳 + 原生平台层（取代 006）
- **状态**：已接受
- **决策**：不重写完整 Flutter 客户端；WebView 直接加载 `dsh web` 官方 Web UI，Kotlin 只做前台服务、通知、省电放行、引擎启停、发热提示。
- **理由**：直接复用官方 Web UI 与 slots 体系；把工程量集中在「让引擎活着」而非重画界面。
- **后果**：launch token → cookie、覆盖 Host 头、不带 Origin 必须实现；厂商 ROM 后台策略需逐档适配；连续两次启动失败进安全模式。

### ADR-013 手机侧能力 App 内置，不做 dsh 插件（取代 ADR-011、修订 ADR-012）
> **v2.3 状态**：**「App 自研渲染器 / App 内置 UI」条款已被 ADR-015 取代**；本 ADR 的「PC 唯一插件 / 手机不做插件 / Termux 原版 DSH / 协议内置卡片」继续有效。`RENDERER_VERSION_MISMATCH` 已删除。
- **状态**：已接受（D-003，2026-11-13），部分修订（D-004）
- **决策**：PC 侧保留 `dsh-wb-cloud-sync` 作为**唯一插件**；手机侧不引入 Cordis、不装 bundle、不注 slots；Termux 只跑原版 `dsh web`；工具卡改为协议内置卡片。
- **不推翻**：ADR-007 / 008 / 009 / 010 继续有效。

### ★ ADR-014 UI 单一源码双投放；传输按 Carrier 抽象（D-004）
> **v2.3 状态**：**「ui-bundle 双投放 / 皮肤层」条款已被 ADR-015 取代**；本 ADR 的 **Carrier 抽象、能力声明下沉、TOFU / 公钥 pin、PC 唯一插件、手机不做插件、Termux 原版 DSH** 继续有效。
- **状态**：已接受（D-004，2026-11-13），部分取代（D-005）
- **决策（现行部分）**：`client-core` 以三个 `DshCarrier` 承载链路差异，能力由 carrier 自报（`supportsUplink` / `allowsEndpoint`）；PC 为唯一插件点；手机不做插件；Termux 跑原版 DSH。
- **~~决策（已作废）~~**：~~`ui-bundle` 双投放 / PC 插件托管 UI 资源~~ → 见 ADR-015。
- **取代**：取代 ADR-013 的「App 自研渲染器」条款；ADR-012 的 Kotlin 平台层与 launch token 链路保留。
- **~~后果（已作废）~~**：~~`/__wbsync/ui/*`、`uiBundleVersion`、UI 哈希、Golden Fixture、R-29~~ → 全部删除。
- **社区借鉴（B1–B4，继续有效）**：Carrier 抽象、能力声明下沉、TOFU 主机指纹 + 设备公钥 pin；明确不照搬 PRoot rootfs 与「能力随模式衰减」。
- **不推翻**：ADR-007~012 全部继续有效。

### ★★ ADR-015 官方原生 UI，零皮肤（D-005）
- **状态**：已接受（D-005，2026-11-13）
- **决策**：手机界面完全采用官方 `dsh web` 的窄屏原生呈现；**不写自定义 UI、不写移动皮肤、不托管 UI 静态资源、不装第三方窄屏适配插件**；三档案的 WebView 都直接寻址官方 `dsh web`（本机 `:3080` / SSH `:3081` / Relay 反代）。
- **理由**：v0.2.2-rc.1 已内置移动端适配（软键盘、窄屏布局、设置页全屏横向导航、16px 触屏输入、宽表格局部横滚等）；自写皮肤只增加上游跟随成本且与官方冲突；去掉 UI 层后一致性天然成立，协议字段与测试用例大幅收敛。
- **取代**：取代 ADR-014 的「ui-bundle 双投放 / 皮肤层」全部条款与 ADR-013 的「App 内置 UI」条款；ADR-014 的 Carrier 抽象、能力声明、TOFU / pin、PC 唯一插件继续有效。
- **后果**：删除 `13` §2 的全部字段 / 包 / 用例 / 风险；`pinned-commit.txt` 锁 v0.2.2-rc.1；W1 增官方窄屏冒烟；W15 上游回归加厚；**周期保持 16 周**（省下约 1.5–2 周 FE 工时转回归与真机矩阵）。
- **不推翻**：ADR-007~012 与 B1–B4 全部继续有效。

> 完整方案与删除清单见 `13_官方原生UI收口修订单.md`；逐步执行见 `12_实施步骤手册.md`。
