## 1. 本轮判定

文档包 13 号把「手机侧零插件、零 UI、`dsh.client` 半边只做 PC 桌面设置页」定为最高优先级，
而仓库当前跑的是 P1 实现：820 行 `client.js` 手机端「我的电脑」面板 + 会话内视图，
外加 ADR-012 镜像模式（手机侧落盘、注册表登记、projcache 投影）。
两者在**同一处位置上是互斥实现**，不是字段级差异。

但文档包自身把收口动作排在**未来阶段**：12 号 S-1.3 属 W1 D2–D4 的 Spike、
S-3.3 属 W3，S-0.1 还要求先完成四方会签；13 §8 会签栏全空。
因此本轮采取：**落地 v2.3 基线 + 补齐插件的可执行契约缺口（纯增量）**，
不推翻 2026-11-12/13 刚在真机验证过的成果。

### 三条刻意收紧

1. **不回 `hostToken` 明文**：04 §8 把 `/__wbsync/config` 的用途写成「relayUrl / hostToken / autoConnect」，
   但该路由挂在本机 `webServer`，页面内任意脚本可读。只回 `hostTokenConfigured` 布尔。
   这是对文档字面表述的**有意收紧**：响应体只含布尔值，明文不出现。
2. **不伪造基线**：`dshCommit` 未由部署方注入时回 `null`，不从 `package.json` 猜版本号；
   `engineScope: 'pc-host'` 明示这是 PC 插件自身状态，不代表 Termux 本机引擎的
   启动中 / 安全模式 / 失败等状态（那属于 App 与引擎层）。
3. **`hostId` 不假装隔离**：未配置时回落 `deviceId` 且 `hostIdSource: 'deviceId'`。
   v2.3 的 `(hostId, sessionId)` 命名空间隔离尚未实现，不做表面改名冒充已实现。

### 一处会导致连接失败的配置优先级冲突（未改 `cordis.patch.yml` 的 config 块）

04 §10 的 patch 示例带 `config: { relayUrl: "", autoConnect: true }`。
本仓库 wrapper 的配置优先级是 `...fileCfg, ...env, ...config`——**`apply` 传入的 `config` 最高**。
若把 `relayUrl: ""` 写进 patch，会覆盖 `~/.dsh/wbsync-host.json` 里用户配好的 relayUrl，
装包后插件连不上 Relay。故 patch 层只保留 `id` / `name`，配置仍走 wrapper 四级链。
