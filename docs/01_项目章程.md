## 1. 背景与问题陈述

DeepSeek Harness 的会话是**本地 append-only 事件日志**，落在 `~/.dsh`。这带来三个真实痛点：

1. 离开电脑就无法继续同一会话；手机上看不到、发不进。
2. 现有远程方案（SSH 直连、Web 版带 token URL）要么要求同网络、要么要求手工配端口，缺少账号级设备发现。
3. 社区已有 `dsh-remote`（host 端）与 `dsh-remote-relay`（中继）解决了"连得上"，但没有账号、设备注册表、会话索引这一层，多台 PC / 多手机时体验断裂。

同时，WorkBuddy 的跨端实践给出了一条被验证的产品路径：**账号同步设置与 Memory，任务执行留在 PC，手机经加密中继把指令送回电脑**。关键认知是"同账号 ≠ 同数据"：会话跟随**执行位置**而不是跟随账号；手机作为「远程控制台」时指令在桌面端执行、两端看到同一份会话，手机侧自行发起的任务桌面端看不到。本项目的 BR-1 实测是同一事实在 DSH 上的版本：手机端 DSH 发的消息不会触发 PC 端 `session/event` 探针（`spike/REPORT.md` §4.1.1）。官方功能口径以 `WORKBUDDY-REFERENCE.md` 记录的文档取证为准。

我们要做的，是把这条路径在 DSH 插件生态里复刻一遍，并且做到自托管、可审计；**有意偏离之处**（配对码、正文可见性边界、v1 不做的远程配置与系统通知）在 `WORKBUDDY-REFERENCE.md` 逐条登记。

## 3. 范围边界

### In Scope

- Host 插件（bundle + client 半边）、Relay 服务、CP 控制面、手机 PWA。
- OAuth 账号（Google / GitHub）、设备注册与发现、配对与令牌生命周期。
- 会话索引、路由租约、消费游标、状态点。
- 事件流透传、幂等 prompt、取消、审批/提问转发、队列语义。
- 置顶任务、工作空间增删、设备名、产物卡片回传、定时任务遥控、附件上传。
- 部署文档、运维手册、安全设计、测试与验收。

### Out of Scope

- 云端 Agent 执行 / 云端沙箱。
- 手机端本地 DSH 引擎（PRoot 方案）。
- 会话正文、工作区文件、本地配置上云。
- 多人协作编辑同一会话、IM 助理渠道、跨 PC 会话迁移。
- DSH 内核修改（严禁；若确需内核能力，走 ADR 上游提 issue）。

## 4. 关键假设与约束

| 编号 | 假设 / 约束 | 若不成立的应对 |
|---|---|---|
| A1 | DSH 提供 `session/event` 事件订阅（首参为 session 对象）、`ctx.webServer` 具名路由、`ctx.effect` 可撤销副作用、`sessionPersistence.list()/open(id,'read')`，以及**宿主会话 owner 的 prompt 提交入口** | 锁 commit 后按 05 W1 / 09 R-02 的**三问**做 Spike 验证；任一不过当天上报发起人，不得进入 P1 编码 |
| A2 | 目标 PC 开机、联网、允许移动端连接、保持唤醒 | 产品层显式提示；离线时新建工作空间入口置灰 |
| A3 | 同一会话同一时刻只有一个写入者 | 由 Route Lease 强制，冲突直接 409 而非排队 |
| A4 | DSH Developer Preview 会不兼容变更 | 全项目锁 commit；升级单独立项 |
| A5 | Relay 与 CP 可自托管，用户接受运维成本 | 提供 docker-compose 一键起 + 托管版作为可选 |
| A6 | 手机端用 PWA 即可覆盖主要场景 | v1 不做原生 App；真机验证 WebView 兼容性 |

## 6. 决策机制

- **ADR（架构决策记录）**：凡涉及协议字段、信任边界、存储选型的决策，必须写 ADR，格式见 `03_系统架构设计.md` 附录；由架构师提交、PM + 相关 Owner 会签。
- **接口变更**：`04_接口协议与数据模型.md` 是唯一契约源。任何字段变更必须同步更新文档 + 版本号 + 兼容性说明，禁止"代码先行文档后补"。
- **范围变更**：走变更单，PM 评估对里程碑的影响，超过 3 人日的变更必须上报发起人。
- **冲突升级**：技术路线争议 → 架构师裁定；跨端体验争议 → PM 裁定；安全争议 → 安全 Owner 一票否决。
