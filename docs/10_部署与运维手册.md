# 10 部署与运维手册

> Owner：BE-RL（兼 SRE）｜ 版本 v1.0 ｜ 面向：自托管用户、运维、值班

---

## 1. 部署拓扑

| 组件 | 建议规格 | 端口 | 说明 |
|---|---|---|---|
| Relay | 2C4G（WS 长连，内存敏感） | 443 | 建议独立部署，不与 CP 抢内存 |
| CP + Postgres | 2C4G | 443 / 内网 5432 | 仅元数据 |
| Host PC | 用户自有 | **无入站** | 主动 WSS 外连 |
| 域名 | `relay.example.com` / `cp.example.com` | — | 各一张证书 |

最小自托管：docker-compose 一键起 Relay + CP + Postgres，适合个人 / 小团队。

---

## 2. 前置条件

- Node.js ≥ 22（**仅 Relay 运行时**，使用原生全局 WebSocket）；**构建链 / Host 插件 ≥ 24.9**（06 §1 统一口径）。Spike 取证脚本在 Node 22 上即可运行，不需 24.9。
- pnpm 11.x；DSH 桌面端或 `web` profile，**版本 ≥ 项目 pinned commit 对应版本**。
- Google / GitHub OAuth 应用，回调地址配到 CP。
- 域名与 TLS 证书；禁止生产使用自签证书跳过校验。
- Host PC 已完成：开启「允许移动端连接此设备」、「保持唤醒 / 锁屏可运行」；macOS 另设「合盖不睡眠」。

## 3. 一键部署（自托管）

```bash
git clone <repo> && cd wb-cloud-sync/deploy
cp .env.example .env
# 至少填写：
#   CP_OAUTH_GOOGLE_ID / CP_OAUTH_GOOGLE_SECRET
#   CP_OAUTH_GITHUB_ID / CP_OAUTH_GITHUB_SECRET
#   RELAY_HOST_TOKEN=<随机高强度串>       # Relay ↔ Host 服务间信任
#   ADMIN_TOKEN=<随机高强度串>            # 管理台
#   POSTGRES_PASSWORD / PUBLIC_BASE_URL
docker compose up -d
docker compose logs -f relay control-plane
```

验证：

```bash
curl -s https://cp.example.com/healthz
curl -s https://relay.example.com/manifest.webmanifest   # 必须无鉴权可访问
```

> `/manifest.webmanifest` 必须无鉴权静态提供：浏览器拉 manifest 不带 cookie，走不了代理，否则 PWA 装不上。

## 4. Host 插件安装

```bash
# 方式 A：npm / tarball（推荐，避免 pnpm allowBuilds 授权）
dsh plugin --profile web add dsh-wb-cloud-sync
# 或
dsh plugin --profile web add ./dsh-wb-cloud-sync-0.1.0.tgz

# 完全退出桌面版后执行，重启桌面版即生效
```

> 从 GitHub 直装时 pnpm 可能因 `allowBuilds` 拦截 git 依赖的构建脚本；若必须走源码，按报错把允许 key 写进 profile 的 `pnpm-workspace.yaml` 再重试。**不要让用户做这项授权**，优先交付 tarball / npm 包。

**首次安装后必须重启一次 DSH**：client 半边（设置页 / 侧栏按钮）的包元数据在进程内有缓存，重启后才出现。

### 配置

打开 DSH 设置 → 「手机连接」：

| 配置项 | 说明 |
|---|---|
| 中继地址 | `https://relay.example.com` |
| HOST_TOKEN | 与 Relay 部署时一致（服务间信任边界） |
| 启动时自动连接 | 默认开 |
| 允许移动端连接此设备 | 必须显式开启，否则设备对手机不可见 |

配置持久化于 Host 侧 storages（如 `/storages/dsh-remote/config.json` 同层），设备与配对状态在 `$DSH_HOME/mobile-remote/devices.json`。

### 验证插件已挂载

```bash
dsh --profile web --dump-config | grep wb-cloud-sync
curl -s http://127.0.0.1:3080/__wbsync/status
```

## 5. 手机端接入

1. 手机浏览器打开 PWA 地址，用**与 PC 相同的 OAuth 账号**登录。
2. PC 设置页点「生成配对码」（6 位，10 分钟有效）。
3. 手机输入配对码 → 自动完成挑战响应 → 得到设备令牌，静默重连。
4. 主页 →「选择设备」→ 选中在线 PC。
5. 发一条指令验证：PC 端同一会话应立即出现。

> 二维码仅作打开/下载引导，**不参与配对**。设备关系持久保留，一次配对永久有效；重新配对会自动替换该设备旧令牌。

## 6. 日常运维

### 监控指标

| 指标 | 告警阈值 |
|---|---|
| 在线 Host 数 | 突降 > 50% |
| 帧延迟 P95 | 跨网 > 800ms 持续 5min |
| 错误码 `HOST_OFFLINE` 占比 | > 20% |
| `ENDPOINT_NOT_ALLOWED` 计数 | 突增（可能越权尝试） |
| `NO_PROGRESS` 触发次数 | > 10/min |
| 补齐失败率 | > 0 |
| 文件通道出网字节 | **> 0 即告警**（隐私红线） |

### 日志

结构化字段：`ts, level, component, accountId, deviceId, sessionId, seq, event, code, traceId`。
**禁止**打印事件 `data`、令牌、文件内容、本地绝对路径；CI 有正则扫描。

### 管理台

`https://relay.example.com/admin`（`--admin-token` 启用）：

- 设备总览（全部 / 在线 / 离线筛选）
- 配对码与有效期、令牌指纹
- 断开手机 / 吊销设备 / 删除设备
- 一键吊销全部手机会话（Relay 侧作废令牌并断开在线连接）
- 单活跃令牌状态、孤儿与 30 天前已吊销令牌加载时自动清理

## 7. 故障排查

| 现象 | 可能原因 | 处置 |
|---|---|---|
| 手机看不到设备 | PC 未开「允许移动端连接」/ 未装 client 半边 / 未重启 DSH / Host 未连上 Relay | 依次查设置页开关 → `--dump-config` → 重启 → `relay` 日志看 `host/register` |
| 设置页没有「手机连接」入口 | client 半边元数据缓存 | 重启一次 DSH |
| 请求 409 `HOST_OFFLINE` | Host 离线 / 锁屏休眠 / WS 断开 | 检查 PC 保持唤醒；确认 `host/heartbeat` 15s；恢复后应静默重连 |
| 消息不出现在 PC | Route Lease 冲突 / 幂等误判 / 宿主提交入口异常 | 查 `ROUTE_CONFLICT`、幂等表、`session/event` 是否发出 |
| 消息重复 | `clientMsgId` 未生成或用了随机新值 | 检查客户端幂等键稳定性；服务端去重窗口 24h |
| 手机刷出 token 碎片 | `assistant/chunk` 未折叠 | 检查客户端 Surface 渲染逻辑（TC-1.3） |
| 断网后历史缺一截 | 用了时间戳当游标 | 必须改用连续 `seq` + `sinceSeq` |
| 审批卡住、琥珀点不消 | `$events/result` 未回传 | 查审批面板与 `ws-frame` 透传日志 |
| PWA 装不上 | `/manifest.webmanifest` 被鉴权拦截 | 改为无鉴权静态提供 |
| 插件卸载后路由仍在 | 注册未交 `ctx.effect` | 修复 disposer；验证 TC-4.10 |
| 构建失败 | Node < 24.9 / `--no-experimental-strip-types` / pnpm 版本 | 按 `06` 环境基线对齐 |
| 令牌泄露 / 手机丢失 | — | 管理台吊销 → 在线连接断开 → 重新配对；删除写墓碑不复活 |

## 8. 升级与回滚

### 升级顺序（**协议先行**）

```
1. PROTOCOL.md / 契约版本  → 2. Relay + CP  → 3. Host 插件  → 4. PWA
```
不兼容变更升 `wbsync/2`，Relay 至少同时兼容 1/2 两个版本 90 天；新增事件类型一律带 `ignorable: true`。

### DSH 上游升级

**单独开 ADR**，禁止在迭代中途 `pnpm update`：

1. 更新 `pinned-commit.txt` 候选值。
2. 跑全量契约测试 + E2E + 混沌。
3. 列出破坏性变更清单（重点：`session/event`、`webServer`、`sessionPersistence`、宿主提交入口）。
4. 灰度验证后才合入。

### 回滚

| 组件 | 回滚方式 |
|---|---|
| Relay / CP | 蓝绿切上一版本镜像；Postgres 迁移需可逆向 |
| Host 插件 | `dsh plugin remove` + 配置备份自动还原；切回上一 `dsh --profile` |
| PWA | 静态资源版本回退 |
| 会话数据 | **不需要回滚**：`~/.dsh` 日志从未被改写；崩溃由 resume 追加 `interrupted` 收尾，禁止手工截断 |

## 9. 备份

- **CP Postgres**：每日全量 + WAL；只含元数据，体量小。
- **Host `~/.dsh`**：用户自行备份即等于备份全部对话历史（事件日志是唯一真源）。
- **禁止**用网盘做 `~/.dsh` 双向同步——追加式日志会被撕裂；要做就走事件流 / resume 方案。
- 令牌摘要、墓碑、设备档案随 CP 备份；恢复后墓碑仍生效。

## 10. 用户须知（写进产品引导页）

1. 电脑需**开机、联网、开启允许移动端连接、保持唤醒**；锁屏/休眠会断连。
2. 手机和电脑登**同一 OAuth 账号**，但**同账号 ≠ 同数据**：会话跟随执行位置，不跟随账号。
3. 手机查看历史消息需要对应 PC 在线；离线只能看会话索引与状态点。
4. 新开任务是全新会话，不继承上一任务上下文；一件事请在同一个任务里继续聊。
5. 任务执行中发消息会进队列、共享上下文、不打断；想立刻停用「停止」。
6. 文件与产物本体始终留在电脑，云端只流转元数据与临时下载票。
