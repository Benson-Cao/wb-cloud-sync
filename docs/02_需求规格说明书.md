## 3. 功能需求

### FR-1 账号与设备发现（P0 基础）

- FR-1.1 支持 Google / GitHub OAuth 登录；同一 OAuth 主体视为同一账号。
- FR-1.2 Host 插件启动后向 CP 注册：`deviceId`、系统设备名（取「关于本机」）、平台、`capabilities`、`relaySessionId`。
- FR-1.3 CP 维护 `online / lastSeen`；Host 心跳 15s，超过 45s 判离线。
- FR-1.4 手机端「选择设备」列出该账号下所有 Host，显示在线状态与状态点。
- FR-1.5 设备关系持久保留，一次配对永久有效；重新配对自动替换该设备旧令牌。
- FR-1.6 电脑改名后，下次连接自动同步到手机端显示。
- **明确**：二维码仅作 App / PWA 下载引导，不参与配对。

### FR-2 配对与令牌（P0 基础）

- FR-2.1 PC 端需显式开启「允许移动端连接此设备」；未开启时设备对手机不可见。
- FR-2.2 配对码 6 位、10 分钟 TTL，设备 + IP 维度限速 5 次/分钟。
- FR-2.3 配对码换取一次性挑战（60s），HMAC-SHA256 挑战响应完成后签发设备令牌。
- FR-2.4 令牌以 SHA-256 摘要落盘；支持持令牌静默重连。
- FR-2.5 单设备仅一个活跃令牌；吊销写入墓碑，重启不复活；管理台可一键吊销全部手机会话。

### FR-3 会话索引与路由（P0 基础）

- FR-3.1 Host 启动时全量上报本地会话索引，之后增量上报。
- FR-3.2 索引字段：`sessionId / ownerDeviceId / workspace / title / pinned / state / lastSeq / lastActiveAt / headerRef`。**不含事件正文**。
- FR-3.3 `state` 四态：运行中（蓝）、待审批/提问（琥珀）、已完成一轮（绿，打开即清零）、不可读（红）。
- FR-3.4 Route Lease：记录会话当前写句柄归属 Host；租约冲突返回 409，不排队。
- FR-3.5 置顶任务分组顺序与 PC 端一致；手机端仅查看，置顶与调序在 PC 端操作。
- FR-3.6 手机可新建工作空间（设备离线时入口不可用）；PC 端移除工作空间后手机列表同步移除，若正作为当前上下文则自动退出并提示。
- FR-3.7 「新开任务 = 全新会话/沙箱」，不继承上一任务上下文；继续聊必须在同一会话内。

### FR-4 事件流与消息投递（P0 核心）

- FR-4.1 Host 订阅 DSH 会话事件，**原样透传 `seq`**，不自编号、不改序。
- FR-4.2 事件字段：`type / seq / time / data`，可选扩展 `surfaceOp / sourceEventSeqs`。**实测宿主不下发 `ignorable` 字段**（667 条样本中 0 次），客户端一律「白名单投影 + 未知类型默认跳过」，不得因未知类型拒绝整会话。
- FR-4.3 手机端按 Surface 规则渲染：仅 `system/message`、`user/message`、`assistant/message`、`tool/result` 投影成消息；`turn/*`、`step/*`、`request/header`、`todo/write` 等作为结构/过程信息处理。**实测日志不含 `assistant/chunk`**（流式分片不落盘），无需 chunk 折叠；`tool/call` 与 `tool/result` 按 `sourceEventSeqs` 配对；宿主自带 `surfaceOp` 投影指令，客户端据此更新视图而非自行重算。
- FR-4.4 断线重连携带 `sinceSeq`，服务端按连续前缀补齐；禁止用时间戳做游标。
- FR-4.5 `session/prompt` 携带 `clientMsgId` 做幂等；**`clientMsgId` 应直接映射宿主 `prompt(request)` 的 `requestId`**，宿主已按 `message.source.rpcId` 原生去重，重复返回 `{accepted:true}` / `duplicate`，不产生第二条 `user/message`。Host 侧不再自建幂等表（ADR-008）。
- FR-4.6 手机**永不自开写句柄**；写入必须由该 Host 的会话生命周期 owner 完成。
- FR-4.7 执行中的消息进队列、共享同一份上下文、轮次结束后按序处理；「停止」走独立 `session/cancel`，与队列语义分离。
- FR-4.8 `session/cancel` 后由 DSH 侧按 `aborted` 收尾；崩溃导致的悬空轮次由 resume 合成 `interrupted` 收尾，不由我们修日志。
- FR-4.9 压缩事件 `compaction/*` 遮蔽旧节点但日志原文不变；客户端按投影结果更新视图，不得回写。

### FR-5 审批与提问（P1）

- FR-5.1 工具审批、用户提问、计划评审经 `$events` 流转发给手机。
- FR-5.2 桌面端与手机端「先答先得」；手机作答经 `$events/result` 回传。
- FR-5.3 琥珀状态点是**阻塞**不是通知，不会因"看一眼"消失，答完才清。

### FR-6 产物与附件（P1）

- FR-6.1 PC 产出的文件以产物卡片展示在手机对话中，支持预览、全部产物列表、单/批量保存分享。
- FR-6.2 支持导出到手机（PDF / DOCX / Markdown）或导出到在线文档。
- FR-6.3 手机可拍照、选照片/视频、选文件发给 PC；上传走临时票 + 分片，落盘到 PC 工作区。
- FR-6.4 **文件本体不出 PC**：CP/Relay 只流转元数据与按需下载票，不落盘工作区内容。

### FR-7 定时任务（P2）

- FR-7.1 手机描述任务 + 选频率（每天/每周/每月），保存后由 PC 按设定时间执行。
- FR-7.2 任务定义与账号绑定，任意已登录设备可查看与管理。

### FR-8 多设备（P1）

- FR-8.1 一个账号可绑定多台 Host；手机按设备档案切换，每台一份地址 + 令牌。
- FR-8.2 协议无需因多主机扩展；多主机是纯客户端能力。
- FR-8.3 Host 离线时，Relay 对 `/d/<deviceId>/*` 立即返回 409，不悬挂等待。

## 4. 非功能需求（NFR）

| ID | 类别 | 要求 |
|---|---|---|
| NFR-1 | 性能 | 事件端到端 P95：局域网 < 300ms、跨网 < 800ms；Relay 帧 ≤ 64KiB 保序搬运 |
| NFR-2 | 可靠性 | 断线补齐 100%；10s 无进度防悬挂；Relay SLO 99.5% |
| NFR-3 | 一致性 | 单写者、幂等、seq 连续；不允许双端同时写 |
| NFR-4 | 隐私 | 工作区文件、会话正文、本地配置 0 上云；出网流量审计可证 |
| NFR-5 | 安全 | 见 `08`；默认拒绝所有高危权限，逐项显式授权 |
| NFR-6 | 兼容性 | Host 插件覆盖 Windows / macOS / Linux；PWA 覆盖 iOS Safari / Android Chrome |
| NFR-7 | 可维护 | 不 fork DSH；所有注册经 `ctx.effect` 可逆；卸载后无残留路由/定时器/监听 |
| NFR-8 | 可观测 | 结构化日志、`seq` 打点、在线设备数、帧延迟直方图、错误码计数 |
| NFR-9 | 可部署 | docker-compose 一键起 Relay + CP；Host 侧 `dsh plugin --profile web add <tgz>` |
| NFR-10 | 可用性依赖 | PC 需开机、联网、开启「保持唤醒」；锁屏/休眠断连需产品层提示 |

## 5. 关键业务规则

- **BR-1 同账号 ≠ 同数据**：会话跟随"执行位置"，不跟随账号。云端不产生会话。
- **BR-2 一个会话一个写入者**：Route Lease 是硬约束，违反即 409。
- **BR-3 视图可多、真源唯一**：`~/.dsh` 事件日志是唯一真源，所有端都是它的投影。
- **BR-4 未知事件宽容**：白名单之外的事件默认跳过，**不依赖服务端 `ignorable` 标记**（实测宿主不下发），不中断渲染。
- **BR-5 新任务隔离**：新开会话 = 新沙箱，不继承上下文。
- **BR-6 默认最小权限**：手机可控端点由 `allowedEndpoints` 白名单限制，默认仅 `session/*` 与 `$events/*`。

## 6. 验收标准（按里程碑）

### M1（W6，MVP）

1. 同账号手机自动发现 1 台在线 PC，配对成功。
2. 手机发文本 → PC 端同一会话出现，且 PC 回复实时回手机。
3. 拔网 10s 再恢复，消息不丢不重。
4. 同一 `clientMsgId` 重发 5 次，只产生 1 条 `user/message`。
5. PC 执行中手机连发 3 条，全部进队列且按顺序被处理。
6. 卸载插件后，`/api/remote/*` 全部 404，无残留定时器。

### M2（W9，完整体验）

7. 两台 PC + 两台手机，设备切换与状态点正确。
8. 工具审批在手机作答，PC 侧任务继续。
9. 产物卡片可预览并导出 PDF/DOCX/MD。
10. 置顶顺序、工作空间移除、设备改名三处同步一致。
11. Host 离线时对应请求 409，且不悬挂超过 10s。

### M3（W12，GA）

12. 安全审计无高危项；出网审计 0 字节工作区文件。
13. 混沌测试 200 次随机断连，补齐完整率 100%。
14. 性能达标（NFR-1）。
15. 三平台 Host + 两平台 PWA 冒烟通过。
16. 文档齐全，第三方按 PROTOCOL.md 可在 1 天内写出最小客户端。

### 降级验收（09 R-02 方案 B，仅在宿主提交入口不可用时启用）

若 W1 Spike 判定「宿主未暴露提交入口」，MVP 收缩为**只读镜像 + PC 端输入**：手机可看事件流与产物、可审批，但不得由手机注入 `user/message`；对应 M1 验收第 2/4/5 项改为「手机只读可见」，并在 CHANGELOG 标注能力集降级。**严禁以插件自开 `open(id,'write')` 绕过单写者。**
