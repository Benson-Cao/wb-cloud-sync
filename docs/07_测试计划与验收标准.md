# 07 测试计划与验收标准

> Owner：QA ｜ 版本 v1.0 ｜ 门禁来源：`02` §6

---

## 1. 测试策略

本项目**不是普通 Web 应用**：核心风险集中在事件序、写入权、崩溃恢复与网络抖动，而非 UI 交互。因此测试投入按「协议与一致性 > 链路 > UI」分配。

| 层 | 投入占比 | 重点 |
|---|---|---|
| 契约 / 一致性 | 35% | seq 连续、幂等、单写者、错误码、未知事件 |
| E2E 链路 | 30% | 手机 → Relay → Host → 同一会话 |
| 混沌 / 恢复 | 20% | 断连、乱序、重试风暴、Host 崩溃 |
| 性能 / 兼容 | 10% | P95、三平台、双端 PWA |
| UI 交互 | 5% | 队列、状态点、产物卡片 |

---

## 2. 测试环境

| 环境 | 组成 | 用途 |
|---|---|---|
| `local` | 单机 docker-compose（CP+Relay+Postgres）+ 本机 DSH `wbsync-dev` profile | 开发自测 |
| `ci` | ubuntu / macOS / windows 矩阵，临时 `DSH_HOME` | PR 门禁 |
| `e2e` | 1 台独立 Host PC + 真机 iOS/Android + 独立 Relay | 里程碑验收 |
| `chaos` | e2e 环境 + 网络注入代理 | 断连 / 乱序 / 延迟 |
| `staging` | 生产同构，20 人封闭灰度 | W10–W11 |

> 所有 profile 用隔离的 `DSH_HOME`，禁止复用开发者日常 `~/.dsh`，避免污染真实会话日志。

## 3. 用例清单

### TC-1 契约与数据一致性

| ID | 用例 | 预期 |
|---|---|---|
| TC-1.1 | 透传 10 种事件类型，检查 `seq` | 原样、连续、无间隙、不自编号 |

| TC-1.3 | 注入带 `surfaceOp` 与 `sourceEventSeqs` 的真实事件片段 | `surfaceOp` 被正确应用；`tool/result` 按 `sourceEventSeqs` 与 `tool/call` 配对，无孤儿卡片；无 chunk 折叠逻辑 |
| TC-1.4 | `tool/call` 与 `tool/result` 按 `callId` 配对 | 配对正确，无孤儿卡片 |
| TC-1.5 | `compaction/start → summary → end` | 视图缩短，日志原文不变，客户端无回写 |
| TC-1.6 | `turn/end` 各 reason（completed/aborted/max-tokens 等） | 状态点正确；轮内触顶按 `max-tokens` |
| TC-1.7 | `SessionHeader` 含 `parentSession` / `delegationDepth` | 工作空间与谱系展示与 header 一致 |
| TC-1.8 | 未知协议版本 `wbsync/99` 握手 | 明确拒绝并提示升级，不静默降级 |

### TC-3 断线与补齐

| ID | 用例 | 预期 |
|---|---|---|
| TC-3.1 | 手机断网 10s（期间 PC 产出 20 条事件）后重连 `sinceSeq=K` | 补齐 (K, K+20]，0 丢 0 重 |
| TC-3.2 | 重连携带 `sinceSeq` 大于当前 `lastSeq` | 不报错、不回放旧事件 |

## 4. 混沌测试方案

`chaos-proxy` 注入以下故障，随机组合、单轮 200 次：

| 故障 | 注入方式 | 观察点 |
|---|---|---|
| 随机断连 | 每 2–15s 断开 WS | 补齐完整率、重连耗时 |
| 乱序 / 重复帧 | 帧队列 shuffle + 重放 | 客户端按 seq 归位、幂等丢弃 |
| 延迟抖动 | 20–1500ms | P95、超时与退避 |
| Host 进程 kill | `SIGKILL` 后重启 | resume `interrupted` 收尾、Route Lease 释放 |
| Relay 重启 | 滚动重启 | 静默重连、令牌保留 |
| CP 不可用 | 停 Postgres | 降级为本地可读索引，写入明确失败而非静默丢 |

**通过标准**：0 丢事件、0 重事件、0 双写、0 文件外泄、所有失败都有明确错误码。

## 5. 性能基准

| 指标 | 目标 | 采集 |
|---|---|---|
| 事件端到端 P95（局域网） | < 300ms | `host/emit` → `client/render` 打点 |
| 事件端到端 P95（跨网） | < 800ms | 同上 |
| 补齐吞吐 | ≥ 500 events/s | 断线补发速率 |
| Relay 单实例并发 WS | ≥ 500 | 压测 |
| 内存 | 长会话 5000 事件无增长 | RSS 采样 |
| 帧大小 | ≤ 64KiB，保序 | 帧日志 |

## 7. 缺陷分级

| 级别 | 定义 | 响应 |
|---|---|---|
| P0 | 丢/重事件、双写撕裂日志、文件外泄、令牌越权 | 立即停发，当日修复 |

| P3 | 文案、样式、非关键兼容 | 排期修 |
