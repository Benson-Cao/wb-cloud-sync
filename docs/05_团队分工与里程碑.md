## 4. 协作流程

### 分支与评审

- `main` 受保护；功能分支 `feat/<模块>-<简述>`；协议变更分支 `proto/<简述>` 必须 ARC Review。
- 每个 PR 至少 1 名非作者 Review；涉及 `04` 的 PR 需同步更新文档，CI 检查文档 diff 存在。
- DoD：代码合入 + 单测通过 + 协议文档同步 + E2E 用例通过 + CHANGELOG + Review。

### 会议节奏

| 会议 | 频率 | 参与 | 产出 |
|---|---|---|---|
| 站会 | 每日 15min | 全员 | 阻塞项 |
| 协议同步会 | 每周一次 | ARC + 各端 Owner | 契约变更清单 |
| 周会 | 每周 30min | 全员 + 干系人 | 进度 / 风险 / 决策 |
| 里程碑评审 | M1/M2/M3 | 全员 + 发起人 | 门禁通过/不通过 |
| ADR 评审 | 按需 | ARC + 相关 Owner | 决策记录 |

### 沟通与文档归属

- 每个模块 Owner 认领自己那份文档（`00` 索引表），PM 统一收口版本与命名。
- 决策不留在大群聊天里：结论必须回写 ADR 或协议文档，否则视为未决策。
- 阻塞超过 4 小时必须升级到 PM。
